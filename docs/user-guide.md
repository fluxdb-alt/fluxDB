## 1. 启动与主界面

### 1.1 从源码启动

1. 安装 [Rust 工具链](https://rustup.rs)。
2. 克隆项目并进入项目目录：

   ```bash
   git clone https://github.com/fluxdb-alt/fluxDB.git
   cd fluxDB
   ```

3. 启动桌面端：

   ```bash
   cargo run -p fluxdb-desktop
   ```

首次编译耗时通常较长。应用启动后，如果左侧没有连接，可点击“添加连接”开始配置。

### 1.2 认识主界面

![FluxDB 主界面](screenshots/home_page.png)

主界面主要分为以下区域：

1. **连接侧边栏**：管理连接、分组、数据库、Schema 和表对象。
2. **标签栏**：承载首页、查询编辑器、数据表、建表、备份、用户权限、设置等页面。
3. **工作区**：显示当前标签页的编辑器、表格、结果或配置内容。
4. **消息提示**：保存、复制、执行、报错等轻量反馈会显示在主窗口中。

常见操作：

- 单击连接或对象左侧箭头：展开或收起节点。
- 双击表：打开数据浏览与编辑页。
- 右键连接、数据库、Schema 或表：打开对应操作菜单。
- 点击标签页关闭按钮，或按 `⌘W`：关闭当前标签页。
- 按 `⌘1`：显示或隐藏连接侧边栏。

## 2. 新建数据库连接

### 2.1 打开新建连接窗口

可使用任意一种方式：

- 点击左侧“连接”标题栏右侧的“添加连接”。
- 首页没有连接时，点击“添加连接”。
- 首页快捷操作中点击“新建连接”。

![新建连接](screenshots/new_connection.png)

### 2.2 选择数据库类型

当前可实际创建和使用的连接包括：

| 类型 | 主要连接信息 | 常用默认端口 |
| --- | --- | ---: |
| MySQL / TiDB | 主机、端口、用户名、密码、数据库、URL 参数 | 3306 |
| PostgreSQL | 主机、端口、用户名、密码、数据库、URL 参数 | 5432 |
| SQL Server | 主机、端口、用户名、密码、数据库、Schema、实例名 | 1433 |
| Oracle | 主机、端口、用户名、密码、Service Name 或 SID、登录身份 | 1521 |
| SQLite | 本地数据库文件路径 | 无 |
| Redis | 主机、端口、用户名、密码、参数 | 6379 |
| MongoDB | 连接串（`mongodb://` / `mongodb+srv://`）、主机、端口、SRV、用户名、密码、默认库、认证库 | 27017 |

MongoDB 连接建议直接粘贴连接串导入，详见 [MongoDB 支持](mongodb.md)。

### 2.3 填写连接信息

1. 在“名称”中填写便于识别的连接名，例如“本地 MySQL”或“生产只读库”。
2. 选择连接颜色。颜色用于在连接树和查询上下文中快速区分环境。
3. 按数据库类型填写主机、端口、账号等信息：
   - MySQL、TiDB、PostgreSQL：数据库可按实际需要填写；连接后也可以在树中切换数据库。
   - SQL Server：使用 SQL Server 认证，填写主机、端口、用户名、密码和登录默认数据库；Schema 留空时连接后读取默认 Schema，读不到时使用 `dbo`。
   - Oracle：填写主机、端口、用户名和密码，并选择用 Service Name 还是 SID 定位实例；绝大多数 12c 及以上实例应填 Service Name（例如 `FREEPDB1`），只有旧实例或明确要求时才用 SID。
   - SQLite：点击文件选择按钮，选择现有数据库文件。
   - Redis：ACL 未启用时用户名可以留空；密码按服务器配置填写。
4. 如连接串包含额外参数，可填写“URL 参数”或“参数”。
5. 点击“测试”。底部显示连接成功后，再点击“保存并连接”。

如果测试失败，依次检查主机、端口、账号密码、目标数据库、服务器监听地址、防火墙及账号来源地址限制。

### 2.4 配置 TLS/SSL

MySQL、TiDB、PostgreSQL 和 Redis 可在“TLS/SSL”页签中配置加密连接：

1. 开启“启用 TLS”。
2. 按服务端要求选择 SSL 模式。
3. 需要双向认证时，分别选择 CA 证书、客户端证书和客户端密钥。
4. 如证书校验使用的主机名与连接地址不同，填写“SNI / 主机名”。
5. 生产环境建议保持“校验服务器证书”开启。

### 2.5 配置 SSH 隧道

数据库只能通过跳板机访问时：

1. 打开“SSH 隧道/代理”页签。
2. 开启“启用 SSH 隧道”。
3. 填写跳板机主机、端口和 SSH 用户名。
4. 选择密码或私钥认证，并填写对应凭据。
5. 返回底部点击“测试”，确认隧道和数据库连接均正常。

### 2.6 高级设置

- MySQL / TiDB：可配置连接和查询超时、字符集、TCP 保活等选项。
- PostgreSQL：可配置建连超时、查询超时、应用名、默认 Schema、TCP 保活，以及是否显示其他数据库和系统 Schema。
- SQL Server：可配置建连超时、查询超时和应用名；命名实例必须同时填写实际端口。查询标签会复用同一 SQL Server 会话，因此跨次执行可保持事务、临时表和会话级 `SET` 状态；超时或点击“停止”会关闭该连接以终止服务端执行，结果状态需要重新核对。
- Redis：可配置连接复用、超时、TCP 保活及拓扑相关选项。

不确定时保留默认值即可。

### 2.7 凭据保存说明

连接密码保存在应用数据目录的 `fluxdb.sqlite` 中（`connection_secrets` 表，以 `connection_id` + `secret_kind` 定位，每条含独立的 `nonce` 和 AES-256-GCM `ciphertext`）；连接表不保存密码、密文或凭据引用。默认使用程序内置密钥，不访问系统钥匙串，启动时不会要求输入电脑密码。

可在应用数据目录的 `config.toml` **顶层**手动添加 `connection_secret_key = "<64 位十六进制字符>"` 覆盖默认密钥；软件设置中没有该项，保存普通设置也不会擦除它。应在**首次保存凭据前**设置自定义密钥。已有密文后直接修改或删除该项会导致解密失败，程序会拒绝用新密钥覆盖；请先备份配置与数据库。内置密钥或与数据库同时可读的配置文件只能防止数据库中出现明文，不能防止能读取程序/配置的攻击者解密。

旧凭据不自动迁移、不会被主动删除；升级后请在连接编辑框中重新输入密码并保存一次。

### 2.8 SQL Server 连接

SQL Server 首版使用 SQL Server 认证（用户名 + 密码），不支持 Windows 集成认证。连接参数按以下方式填写：

| 参数 | 说明 |
| --- | --- |
| 主机 / 端口 | 默认端口 `1433`。使用显式 TCP 端口连接；若连接字符串或服务器配置使用命名实例，请向管理员确认实例实际监听端口并直接填写。 |
| 数据库 | 登录后的默认数据库。留空表示使用登录账号的默认数据库；连接后可在对象树中切换到其他有权限的数据库。 |
| Schema | 对象的默认 Schema。留空时连接后读取 `SCHEMA_NAME()`，无法读取时使用 `dbo`。生成对象 SQL 时始终显式带 Schema，不能依赖当前连接的默认 Schema。 |
| 实例名 | 首版不解析 SQL Browser / UDP 1434。填写实例名会提示必须改用显式端口，因此请清空实例名并填写实际端口。 |
| 应用名 | 服务端 `APP_NAME()` 中显示的名称，默认 `FluxDB`。 |

“TLS/SSL”页签提供三档加密模式：

- **关闭加密**：不要求全链路加密。TDS 登录包仍会加密，但登录后的业务通信可能是明文；只应在受控网络中使用。
- **要求加密**：要求加密连接，并校验服务端证书。生产环境优先使用该档；需要 CA 或主机名与证书匹配，否则连接会失败。
- **信任服务器证书**：要求加密，但接受自签或不受信任的证书。适合测试环境和无法部署 CA 的内网实例；生产环境应确认这是否符合安全要求。

权限建议：

- 只读查看优先使用最小权限账号，例如授予目标数据库的 `CONNECT`、对业务 Schema 的 `SELECT` 和 `VIEW DEFINITION`；需要编辑数据或结构时再按需授予 `INSERT`、`UPDATE`、`DELETE`、`ALTER` 等权限。
- SQL Server 的元数据可见性受权限控制。账号看不到的对象不会出现在对象树中；`VIEW DEFINITION` 不足时，列、索引、约束、DDL 或触发器信息可能为空或加载失败。这不是对象不存在，应让管理员检查数据库角色和对象级权限。

AI 对 SQL Server 使用与编辑器相同的 T-SQL 方言：只读查询、`db.describe_object` 和只读页面上下文可用；写语句需要人工审批。只读入口除客户端分类外，还会把语句放进事务并在结束后回滚，写操作不会被提交。执行计划使用 `SET SHOWPLAN_ALL` 在独立会话生成，不会执行被解释的语句。`xp_cmdshell`、`OPENROWSET`、`sys.sql_logins`、`sys.dm_exec_sessions` 等越权能力与系统视图会被拒绝或降级为需授权。

SQL Server 的存储过程和函数会出现在对象树对应分组中。左键点击对象可查看只读 DDL；读取定义需要账号具备相应 `VIEW DEFINITION` 权限，否则会显示权限错误。
- `sysadmin` 或 `db_owner` 能看到全部对象并执行多数操作，但不应作为日常桌面连接的默认账号。备份、恢复和跨库操作需要的权限高于普通浏览，应按任务单独授权。
- 应用当前不会把密码写入普通连接配置、日志或 AI 上下文；保存连接前请确认只使用测试库或已授权账号。

备份与导入边界：

- 表数据导入已支持，可通过文件解析、列映射和批量参数绑定写入表。identity 列在导入时会按列信息使用 `IDENTITY_INSERT`；清空模式使用 `TRUNCATE TABLE`，被外键引用时会被服务端拒绝，不会静默改为 `DELETE`。
- 表级备份和恢复仍在接入中，当前会明确提示不支持，不会用 `BACKUP DATABASE` 冒充表级备份。数据库级物理备份涉及服务端文件路径、权限和恢复覆盖策略，需在独立功能中处理。
- “导出数据”仍可对表数据进行导出；首次打开导出窗口时，如果预览接口返回不支持，导出按钮可能无法继续，请以当前界面的错误提示为准。

### 2.9 Oracle 连接

Oracle 的“Schema”就是“用户”，没有独立的数据库层级，因此对象树按 Schema 组织。连接参数按以下方式填写：

| 参数 | 说明 |
| --- | --- |
| 主机 / 端口 | 默认端口 `1521`。填写监听器实际监听的主机和端口。 |
| 连接方式 | 在 Service Name 与 SID 之间二选一，二者不能混用。12c 及以上的多租户实例通常用 Service Name，并需指明要进入的 PDB（例如 `FREEPDB1`）。 |
| 用户名 / 密码 | 登录账号。未加双引号创建的账号和对象名在 Oracle 中一律大写折叠，界面上按大写显示；需要用引号保留大小写时，对象名本身已含大小写。 |
| 登录身份 | 默认普通连接。`SYSDBA` / `SYSOPER` 必须显式选择，不会从用户名（例如 `sys`）自动推断。 |
| 默认 Schema | 可选。连接后执行 `ALTER SESSION SET CURRENT_SCHEMA`，只影响未限定名的解析，**不增加任何权限**。 |
| Wallet | 可选。填写本地 Wallet 目录；目录本身不是凭据，但 Wallet 口令按同类凭据处理，不会明文落盘。 |

对象定位使用 `"OWNER"."TABLE"` 两段式名称：Oracle 不区分“数据库.表”，必须带上所属 Schema。未加引号的标识符按大写处理，因此 `select * from orders` 实际访问的是 `ORDERS`；对象名含小写或特殊字符时必须加双引号。

数据展示与编辑需要注意：

- `DATE` 类型在 Oracle 中自带时分秒，界面上按日期时间处理，不要当成纯日期。
- `NUMBER` 按精确数值读取，不会转成浮点数后再显示，避免大整数和小数精度丢失。
- `CLOB` / `BLOB` 只做有界预览，不整块载入内存。字符 LOB 超过 4000 字符时，格子与详情都标为「仅预览」；打开详情会在后台自动读取完整值（上限 8 MiB），读到后才能编辑。带预览的单元格不能就地编辑，导出、复制、导入与逻辑备份会拒绝半截值，避免用片段覆盖完整数据。
- 分页使用 12c 及以上的 `OFFSET … FETCH NEXT`，列排序会补上唯一键以保证翻页稳定；没有唯一键的表，翻页顺序只能按实际执行计划确定。

导出与备份边界：

- “导出数据”是本机逻辑导出：导出 DDL 加逐页读取的数据，不是服务器端 Data Pump 备份，也不是数据库级灾难恢复方案。
- 每页是独立查询，跨页不共享同一个一致性快照；导出期间有并发写入时，导出结果可能包含不同时点的数据。需要严格一致的快照应使用 Oracle 自身的 Data Pump 或闪回能力。
- Data Pump 的 `DIRECTORY` 是服务器端路径，桌面端无法直接写入，因此当前不提供“一键备份”按钮。

AI 对 Oracle 使用 `OracleDialect` 解析，只读判定比 MySQL 类数据库更严格：`SELECT … FOR UPDATE`、`seq.NEXTVAL`、`utl_*` / `dbms_*` 包成员、以及通过同义词、视图或 `@dblink` 间接访问的对象都不会被判为只读，需要人工审批；`EXPLAIN PLAN FOR` 会写入计划表，同样按写操作处理。提交期间断网时结果未知，不会自动重放写语句。

## 3. 管理连接与数据库

### 3.1 打开、关闭和刷新连接

在左侧右键连接，可执行：

- **打开连接 / 关闭连接**：建立或释放当前数据库会话。
- **刷新**：重新加载数据库和对象树。
- **编辑连接**：修改连接参数后重新测试并保存。
- **复制连接**：以现有配置为基础创建一份副本。
- **删除连接**：删除保存的连接及其凭据引用；此操作不会删除服务端数据库。

### 3.2 使用连接分组

1. 点击“连接”标题栏中的“新建分组”。
2. 输入分组名称。
3. 右键连接，选择“移至分组”。
4. 需要移出时，右键连接选择“取消分组”。

建议按环境或项目分组，例如“本地”“测试”“生产”。

### 3.3 管理数据库节点

右键数据库可执行以下常见操作：

- 打开或关闭数据库。
- 置顶或取消置顶。
- 设置默认数据库。
- 新建查询、新建表、执行 SQL 文件或备份。
- 在数据库中查找对象。
- 刷新或删除数据库。

PostgreSQL 数据库下还会显示 Schema。右键 Schema 可新建查询、新建表、设置默认 Schema 或刷新。

> 删除数据库会影响服务端真实数据。请核对连接、数据库名和备份状态后再确认。

### 3.4 管理标签页

右键标签页可以关闭当前、关闭其他、关闭左侧、关闭右侧或关闭全部标签页。包含未保存内容或未提交修改的页面在关闭前会给出确认提示。

## 4. 使用 SQL 编辑器

![SQL 编辑器](screenshots/sql_editor_adapter.png)

### 4.1 新建查询

可使用以下方式：

- 右键 SQL 类型连接、数据库或 PostgreSQL Schema，选择“新建查询”。
- 点击首页“新建查询”。
- 按 `⌘Y`。

如果当前没有明确的连接或数据库，FluxDB 会要求先选择查询作用域。编辑器顶部会显示当前连接和数据库，请在执行前核对。

### 4.2 编写和补全 SQL

- 输入 SQL 关键字、表名或字段名时，编辑器会提供补全建议。
- 按 `Control+Space` 可主动触发补全。
- 光标停在函数括号内（如 `COUNT(`）时，编辑器会显示该函数的参数提示，并高亮当前参数。
  提示只覆盖连接方言的内置函数，自定义函数不显示。
- 按 `⌘/` 可切换当前行或选中行的行注释。
- “美化 SQL”优先格式化选区；没有选区时格式化全文。
- “压缩 SQL”优先压缩选区；没有选区时压缩全文。
- 自动换行按钮可以切换当前编辑器的长行换行方式。

### 4.3 执行 SQL

1. 只执行特定 SQL 时，选中完整语句。
2. 未选中时，把光标放在要执行的语句中。
3. 点击“运行”，或按 `⌘Enter`。

执行优先级为：完整选中语句 → 选中文本 → 光标所在语句。无法确定语句时，应用会提示先选中 SQL 或把光标放入语句。

其他执行方式：

| 操作 | macOS 快捷键 | 说明 |
| --- | --- | --- |
| 执行 | `⌘R` | 编辑器聚焦时执行当前 SQL；会覆盖全局刷新快捷键 |
| 查询结果模式 | `⌘⇧R` | 以 Select 模式执行 |
| 执行计划 | `⌘⇧E` | 对可解释的查询执行 Explain |
| 停止 | 工具栏“停止” | 请求取消正在执行的查询 |

包含高风险更新或删除的 SQL 可能触发二次确认。取消请求发出后，仍应检查服务端数据状态；数据库可能已经完成部分操作。

### 4.4 使用运行参数

SQL 中使用命名参数（例如 `:user_id`）时，运行前会出现“运行参数”窗口：

1. 在“逐个输入”中分别填写每个参数；或切换到“数组输入”批量提供值。
2. 点击“应用并运行”。
3. 参数会转换为 SQL 字面量并写入本次执行文本，请在执行高风险语句前再次检查生成内容。

### 4.5 查看查询结果

结果区会显示：

- 每条语句的成功或失败状态。
- 返回的数据表和分页控件。
- 受影响行数、耗时及执行摘要。
- 查询错误、出错 SQL、复制错误和重试入口。

结果区可以在底部或右侧显示；拖动分隔线可调整编辑器和结果区大小。

### 4.6 保存和复用查询

点击“保存”或按 `⌘S`，可以：

- 保存到本地 SQL 文件。
- 保存到当前连接中，供后续复用。

点击“历史记录”或按 `⌘⇧H`，可以搜索并重新使用历史 SQL。执行历史可能包含业务数据，请按本机数据安全策略管理。

### 5.3.1 大字段的显示与查看

单个字段超过 64 KiB（大文本、JSON、二进制）时不会整份留在内存里，也不会让这一行消失：

- 表格与查询结果里显示有界预览，并注明只是片段；详情面板给出完整字节数。
- 进入单元格详情后按块加载（每块约 256 KiB），点“读取更多”继续往下翻，不会一次读出整份内容；读取期间该按钮变成转圈并暂停响应，状态区同样显示转圈，读完再恢复。
- “下载”会把完整内容流式写入你选择的位置（不会把值复制到剪贴板），二进制字段的“下载”同样先选路径。
- 单元格操作统一放在详情面板“值”标题行，且都用图标按钮（悬停显示名称），大字段与普通字段位置一致：下载图标＝把完整内容存成文件，上传图标＝用本地文件整值替换，双下箭头＝继续读取下一段。
- 总量、已读窗口与加载状态紧随“值”标题排在同一行：总量是浅底小标签，窗口范围是灰字（过长省略，悬停看完整范围），中间细进度轨显示已读部分占全文的比例，末尾色点＋短词表示“仅片段 / 加载中 / 已到底 / 失败”。不再单独占一行。
- 大字段不提供“复制整值”和就地编辑：完整内容需要按块查看或另行下载，避免把上百 MB 文本塞进输入框。
- 页容量按行数控制，不再设置整页 16 MiB 驻留预算；多个小字段合计超过 16 MiB 也会正常收进本页。单格外置失败时查询或导出明确失败，不返回缺行却看似成功的结果。
- 超大字段内容存于本地临时目录（每份结果最多 256 MiB），关闭标签、刷新数据或断开连接即清理。
- 二进制字段（`BLOB`/`VARBINARY`/`bytea`/`RAW`/`IMAGE` 等）在 MySQL、PostgreSQL、SQLite、SQL Server 的表格里只显示“类型 + 字节数 + 十六进制前缀”，正文不会整份读进结果页；要看完整内容请进详情面板按块读取或下载。达梦暂按原值返回，超过 64 KiB 时同样外置成内容引用。
- 各数据库走同一套单格外置规则：单格超过 64 KiB 先外置成内容引用，整页不再按累计字节数截断。SQL Server 与达梦不会再因为页预算直接丢掉整行。

“上传替换”按文件大小走两条路径：

- 小于 16 MiB 的文件一次读入内存、用一条语句写入，这是小文件最快的路径。
- 16 MiB 及以上的文件先把内容流式落到本地暂存目录，提交时按 16 MiB 分块追加到字段：进程内存峰值固定在分块大小，不会随文件变大而上涨，界面也不会因为要把几百 MB 读进内存而卡住。
- 暂存总量受单个归属 256 MiB 配额约束，超过时直接提示并放弃，不会写半份。
- 是否支持分块追加因数据库而异。MySQL、SQLite、PostgreSQL、SQL Server 支持；Oracle、达梦等暂不支持，超过阈值的文件会被拒绝并提示改用较小的文件。
- 追加写法在 MySQL/SQLite/PostgreSQL 上会重写整个字段（代价随已写长度增长），所以分块不宜过小；16 MiB 是在速度和内存之间取的折中值。
- 提交前放弃改动、关闭标签或刷新数据，暂存内容会一并清理。

“上传替换”同时适用于大文本字段（`TEXT`/`LONGTEXT`/`CLOB`/`nvarchar(max)` 等无长度上限的文本类型）和二进制字段，入口与阈值完全一致。文本字段另外有三条约束：

- 上传后单元格先显示为 `LONGTEXT…（共 50.0 MB）` 这类占位值，正文在提交前存在本地暂存区；详情面板可直接按块读出你刚选的文件，确认无误再提交。
- 占位值不是正文：不提供复制、就地编辑与导出，避免把「类型 + 大小」当成数据带走。
- 文件必须是合法 UTF-8，否则直接拒绝并提示，不做替换字符之类的隐式转换。
- 分块追加会回退到 UTF-8 字符边界再写入，因此多字节字符跨块也不会被截断。
- `JSON`/`JSONB` 字段不提供上传替换：分块追加无法保证每一块都是合法 JSON，整值写坏后数据库也读不回来。

## 9. 用户与权限管理

MySQL、TiDB、PostgreSQL、SQL Server、Oracle 和达梦 DM8 连接支持“用户与权限”入口。

1. 右键连接，选择“用户与权限”。
2. 点击刷新，加载用户或角色列表。
3. 选择现有用户进行编辑，或点击新增按钮创建用户。
4. 配置常规信息、登录能力、资源限制、成员关系和对象权限。
5. 可在“SQL 预览”中核对执行语句；该页只读，不负责执行。预览展示与执行同源的完整语句，四种数据库的口令都按草稿如实显示；语句不会进入 SQL 历史、日志或 AI 上下文。
6. 点击顶部“保存”，在弹出的确认框中核对 SQL 后点“执行”，等待成功提示再刷新列表验证。

新建用户一次保存即可完成：账号、成员关系与权限写在同一次保存里，不需要先建号再回来配置。
五种数据库（MySQL / PostgreSQL / SQL Server / Oracle / 达梦）的保存流程一致：点“保存”先弹出
同一个确认框，内容就是“SQL 预览”页的同一份语句，点“执行”才提交。多条建号 DDL 不保证原子性
——MySQL / Oracle / 达梦失败时会把数据库原始错误连同“已执行 N/M 条”一起抛出，PostgreSQL 与
SQL Server 在单事务内整批回滚。按提示刷新后重跑剩余部分即可。

![用户与权限](screenshots/user_admin.png)

SQL Server 第一阶段的“用户与权限”按服务器与数据库两层管理：

打开页面后，在 SQL Server 类型标签旁的“目标数据库”下拉框选择要管理的库；未配置连接
默认数据库时，页面只加载可访问库列表，不自动选库，且“+”按钮保持禁用直到选库完成。
切换会重新加载该库的用户、角色和权限，不修改连接的
默认数据库。只有实际修改了字段才视为未保存变更；打开空白新建表单不会锁定数据库。
存在未保存变更时，先保存或取消更改才能切换。

常规页与其他 SQL 数据库一样使用横向表单，可直接编辑密码、默认库、登录映射和默认 Schema。
所有更改统一通过顶部“保存”提交：先弹出确认框展示本次 SQL（与“SQL 预览”同源），点“执行”才落库。顶部“取消”放弃本地更改。
普通服务端错误会保留表单供修正；通信中断等结果不确定时，禁止直接重试，先点击“刷新”核实。

- 登录名：列出 SQL/Windows 登录名；第一阶段可创建、启停、改密、修改默认数据库和删除 SQL 认证登录名。
- 数据库用户：创建映射到已有 SQL 登录名的用户，修改登录映射和默认 Schema。
- 角色：列出服务器角色和当前数据库角色，管理固定/自定义数据库角色的成员。
- 权限：读取并编辑显式服务器、数据库、Schema 和对象权限，支持 `GRANT`、`WITH GRANT OPTION`、`DENY` 和 `REVOKE`。

权限页会在保留现有权限的同时展开添加面板。选择权限后点击“添加到待保存列表”，新行会立即
出现在列表中并标记“待保存”；添加面板保持展开，可继续添加。待保存行可单独移除，全部提交
仍使用顶部“保存”。

保存时在单事务中按服务器/数据库上下文切换执行，并自动刷新列表。当前不包含 Windows
集成认证、Azure AD、包含数据库用户、列级权限编辑和用户自定义服务器角色；目录里没有显式
权限行也不代表角色没有继承或固定角色隐含权限。撤销 `WITH GRANT OPTION` 权限时 SQL Server
要求 `CASCADE`；预览会明确显示，普通 `GRANT`/`DENY` 不会自动级联。

创建可登录业务账号通常分两步：先在“登录名”页创建 SQL Server 登录名，再在“用户”页
创建映射到该登录名的数据库用户，最后在“角色成员”和“权限”页授予访问范围。上述变更可
同时加入同一个待保存计划并从一次事务执行，不要求逐步提交。
登录名属于服务器级；数据库用户和数据库权限属于“目标数据库”选择的范围。点击“保存”会
立即在同一事务中创建账号；“SQL 预览”只用于核对 SQL，不需要再次确认执行。

权限管理需要当前账号具备读取和修改用户、角色或授权信息的权限。删除用户、撤销权限和修改角色成员关系可能导致业务中断，请先确认依赖该账号的应用和任务。

Oracle 的“用户与权限”按账号（即 Schema）管理，与其他数据库的数据模型不同：

- 左侧列表来自 `ALL_USERS`，会列出当前账号能看到的全部账号名。只有“当前登录账号”自己的角色、系统权限、对象权限和配额可读；选中其他账号时整页显示为不可读，不画成空授权，也不提供撤销入口——把读不到的授权显示成可直接撤销，会诱导出错误的 `REVOKE`。
- 与 MySQL / PostgreSQL / SQL Server 一致，填写的草稿不需要单独“加入变更”：点顶部“保存”先把当前草稿渲染成 SQL 并弹出确认框，确认后才执行；“SQL 预览”页显示同一份语句。**Oracle 的用户/权限 DDL 会隐式提交，失败后无法整批回滚**；失败提示会说明已执行到第几条，此时应刷新并按实际生效情况重跑剩余语句。
- 右侧分五页：**常规 / 角色 / 系统权限 / 对象权限 / SQL 预览**。三份授权清单位于各自页签，每个页签顶部就是对应类型的授权编辑器，不需要先选类型；授权名可手动输入，也可以点右侧下拉从当前账号可转授的候选里选（候选为空时下拉不出现，仍可手填）。点“加入待执行”可继续添加多条，保存时全部并入同一份计划，列表里的每条都能单独移除。
- 口令只进入内存草稿；预览与 MySQL / PostgreSQL 一样按草稿如实显示。执行回执用的是另渲染的脱敏副本，密码不会进入 SQL 历史、日志或 AI 上下文。
- 新建账号默认不能登录，需要同时授予 `CONNECT` 角色；表空间、profile 留空表示使用模板默认值。
- CDB/PDB 场景下公共账号（`C##` 前缀）与本地账号的作用域不同，当前不做自动跨容器切换。

达梦 DM8 复用同一个账号面板，差异只在方言：登录权限是系统权限 `CREATE SESSION`（达梦没有
`CONNECT` 角色），`CREATE USER` 不接受 `PROFILE`（改为建号后 `ALTER USER … PROFILE`），
也没有 `QUOTA … ON …` 子句。其余「一次保存」行为与 Oracle 一致。

## 10. 使用 Redis

### 10.1 打开 Redis 数据库

1. 创建并连接 Redis。
2. 展开连接，选择逻辑数据库。
3. 打开后进入键浏览页面。

![Redis 键浏览与详情](screenshots/redis_detail.png)

顶部搜索框可按 Key 模式查找；可使用搜索历史重复查询，点击“刷新”重新加载，点击“新增键”创建数据。

### 10.2 新增 Key

1. 点击“新增键”。
2. 选择 Key 类型：String、Hash、List、Set、ZSet、Stream 或 JSON。
3. 填写 Key Name。
4. TTL 可留空表示永不过期；填写时确认单位和期望的过期时间。
5. 按类型填写值、成员、分数或字段。
6. 保存后回到键列表确认数据和 TTL。

JSON 类型的值使用带语法高亮的代码编辑器，可用“格式化/校验”按钮美化后保存。服务端加载了 RedisJSON 时写入 JSON 类型键；未加载时自动退回普通字符串存储 JSON 文本，键列表仍按内容把它显示为 json。

### 10.3 查看和编辑 Key

选择 Key 后，详情区会根据类型提供对应操作：

- **String / JSON**：查看、格式化和保存完整值。
- **Hash**：查询、新增、修改或删除字段。
- **List**：查看列表、新增条目或按规则删除元素。
- **Set**：查询、新增或删除成员。
- **ZSet**：查询成员，编辑成员及分数。
- **Stream**：查看和新增 Entry，并查看消费者组信息。

Key 元信息区域可以刷新、修改键名和 TTL。保存前确认键名不会覆盖不应替换的现有数据。超大值可能只显示截断预览，应进入完整值编辑入口后再修改。

![Redis JSON](screenshots/redis_json.png)

### 10.4 Redis Workbench

对 Redis 连接执行“新建查询”会打开 Workbench，而不是 SQL 编辑器。

![Redis Workbench](screenshots/redis_workbench.png)

1. 输入 Redis 命令；输入过程中光标下方会显示当前命令的参数签名，必填参数填完自动消失，也可按 Esc 关闭。
2. 点击“运行”。
3. 每条执行记录会显示命令、状态、执行时间、耗时和响应。
4. JSON 命令结果可在 Text / JSON 视图间切换。
5. 可单独重跑或删除某条执行记录。
6. “历史记录”会按连接和逻辑数据库显示已执行命令。

FLUSH、DEL 等危险命令可能触发二次确认。执行后仍应主动刷新键列表验证结果。

### 10.5 Redis CLI

1. 右键 Redis 逻辑数据库。
2. 选择“Redis CLI”。
3. 在终端中输入命令并回车执行。

![Redis CLI](screenshots/redis_cli.png)

CLI 更接近直接命令行操作，适合熟悉 Redis 命令的用户。高风险命令不会因为在终端中执行就自动变得安全，请先核对当前连接和 DB 编号。

### 10.6 Pub/Sub

1. 右键 Redis 逻辑数据库。
2. 选择“打开 Pub/Sub”。
3. 添加要订阅的频道或模式。
4. 使用发布区域填写频道和消息并发送。
5. 点击已订阅项目可取消订阅。

Pub/Sub 消息是实时的，不会因为关闭页面而在 Redis 中自动补发历史消息。

## 13. 常见问题

### 13.1 连接测试失败

按以下顺序检查：

1. 数据库服务是否已启动并监听填写的地址和端口。
2. 主机和端口是否能从当前 Mac 访问。
3. 用户名、密码和数据库名是否正确。
4. 数据库账号是否允许来自当前地址的连接。
5. TLS 模式、证书和 SNI 是否与服务端要求一致。
6. SSH 跳板机是否可登录，认证方式和目标地址是否正确。
7. 云数据库安全组、防火墙或 VPN 是否放行。

### 13.2 连接成功但看不到数据库或表

- 右键连接或数据库选择“刷新”。
- 右键连接选择“选择显示数据库”，检查目标数据库是否被隐藏。
- PostgreSQL 检查默认 Schema 和“显示系统 Schema”设置。
- 确认账号拥有读取元数据和目标对象的权限。

### 13.3 查询可以运行，但结果不能编辑

结果编辑需要能够可靠识别源表和记录。连接查询、多表查询、聚合结果、缺少主键或唯一标识的结果可能只读。可双击原始表打开数据页后再尝试编辑。

### 13.4 修改了数据但数据库没有变化

表格编辑先保存在本地待提交区。请查看底部是否有待提交数量，并点击“提交更改”；点击“取消更改”、刷新或关闭页面会放弃尚未提交的修改。

### 13.5 备份按钮不可用或备份失败

- 在“设置” → “数据”中配置备份目录。
- 检查目录是否存在且当前用户可写。
- 检测对应数据库客户端工具，必要时重新选择路径。
- 查看备份窗口实时日志中的具体错误。
- 原生工具版本最好与数据库服务端主版本兼容。

### 13.6 Redis 搜索不到 Key

- 确认当前逻辑数据库编号正确。
- 清空搜索条件后刷新。
- 检查 Key 模式是否过于严格。
- 确认账号具备 SCAN 和读取相关数据类型的权限。
- 集群、哨兵或代理环境下，检查连接拓扑配置是否正确。

### 13.7 应用操作后界面没有更新

先等待当前 loading 状态结束，再刷新当前对象。不要在备份、导出、SQL 文件执行或大查询仍在运行时反复点击相同操作。

## 14. 数据安全建议

- 为生产环境连接设置醒目的名称和颜色，并单独分组。
- 日常浏览优先使用只读账号；仅在需要时使用具备写入或管理权限的账号。
- 执行 `UPDATE`、`DELETE`、`TRUNCATE`、`DROP`、Redis `FLUSH*` 等操作前，先确认连接、数据库、Schema 和条件范围。
- 表格批量修改前查看 SQL 预览；条件不明确时取消提交。
- 结构变更、权限变更和批量导入前先备份，并验证备份可恢复。
- 不要把导出的业务数据、数据库密码、私钥或证书提交到 Git 仓库。
- 查询被取消、应用异常退出或网络中断后，应重新连接并核对事务和数据状态，不要仅凭界面提示判断回滚结果。
