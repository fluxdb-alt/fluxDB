# ER 画布视觉与交互改造实施规范

日期：2026-09-20。

> 阶段说明：本文件保留第一阶段的实现背景。继续改造时，以 [ER 关系画布第二阶段规范](er-ui-relationship-canvas.md) 为准。第二阶段明确替代本文的固定网格、仅表头端口和禁止单节点拖动约束；其余兼容的性能、主题和验证要求继续适用。

本文是给实现者的完整文字规格，无需查看或识别截图。用户已认可借鉴 ChartDB 的清爽卡片、drawDB 的关系表达，在现有 GPUI 画布上改善视觉。本文明确取代“所有可见卡片必须等高”的前一阶段约定；保留稳定布局、二维虚拟化、分阶段加载和字段按需读取。

本轮实施本文规定的卡片、画布基础样式、稳定排列、表级连线与选择反馈。不得把本文解释为批准 `er-design.md` 中待确认的 D1–D9 模型。

## 1. 参考与目标

- ChartDB：https://github.com/chartdb/chartdb 。参考紧凑卡片、字段分列、轻量表头和画布层次。
- drawDB：https://github.com/drawdb-io/drawdb 。参考清楚的端点、关系高亮及主外键标识。
- ERD Editor：https://github.com/dineug/erd-editor 。参考类型/字段/约束的对齐。

只借鉴设计原则，使用项目现有 Rust/GPUI 实现，不复制项目源码、图片、品牌或整套 CSS，不引入 WebView。无需打开图片确认效果。

目标观感：浅色画布略灰，表卡片明亮；暗色画布较深，表卡片略亮。卡片外框紧贴实际显示内容，表头清楚，字段排版整齐，连线可辨。避免厚重阴影、每表一种随机颜色、大片空卡片和文字字符图标。

## 3. 画布与工具栏

### 3.1 画布底色与留白

- 使用 UiColors 对应的画布背景、面板、边框及文字 token；若语义不足，在 UiColors 集中补 token 并覆盖明暗主题。
- 初始内容距离画布左侧和上侧各 32 个逻辑像素；不能贴住工具栏分隔线或左边框。
- 背景可用极淡点阵，点间距 20px、直径约 1px，视觉强度低于连线。点阵随世界坐标平移，不能贴在屏幕上不动。
- 点阵必须用一个画布绘制层只画当前视口，禁止每点创建 div 或绘制整个世界区域。若实测产生明显帧开销，保留纯色背景，文档说明即可。

### 3.2 工具栏

- 复用现有工具栏布局，高约 40px；左侧标题为 `数据库名 · ER`，局部模式保留中心表信息。
- 标题旁用弱化文字显示 `N 张表`。关系阶段未完成时显示“关系加载中…”或“关系不完整”，不得用 0 条关系替代未知。
- 不把原始外键字段行数直接称为关系数；只有现有模型能可靠识别关系时才显示关系计数。
- 右侧增加“回到起点”与“重新排列”，使用 gpui-component Button 和现有 AppIcon，不造文字按钮。布局处理中显示 loading/disabled。
- “回到起点”只恢复当前布局的初始 pan，不重读数据库、不重新排列。
- “重新排列”按当前可用宽度显式重新计算网格并回到起点，不清除字段/关系缓存。若已有人工节点坐标能力，按既有保护约定处理，不静默覆盖。
- 保留局部 ER 深度选择、加载错误和重试。不要新增搜索侧栏、缩放滑杆、小地图或未实现功能的占位按钮。

## 4. 节点卡片的详细规格

全部尺寸是 GPUI 逻辑像素，不额外乘 DPI。以下是首版统一参数，不为不同表名写特例。

| 项目 | 数值/规则 |
| --- | --- |
| 卡片宽度 | 260px |
| 圆角 | 复用 UiColors 中最接近 6px 的现有圆角 |
| 普通边框 | 1px，主题柔和边框色 |
| 顶部强调条 | 2px，同一视图使用一致的低饱和强调色，不按表名随机上色 |
| 表头 | 32px 高，横向 padding 10px，浅面板底色 |
| 表名 | 12px，semibold，单行省略；悬停可查看完整限定名 |
| 表头左侧图标 | 14px 表图标，与标题间隔 6px |
| 字段行 | 24px 高，字号 11px，最多显示 8 行 |
| 字段区上下 padding | 各 4px |
| 长表页脚 | 22px 高，字号 10–11px，弱化文字 |
| 投影 | 首版不需要；不能依赖大阴影区分节点 |

### 4.1 高度公式与内容示例

已加载且有 N 个字段时：

`card_height = 2 + 32 + 8 + 24 × min(N, 8) + (N > 8 ? 22 : 0)`

边框像素按实际 GPUI box model 一致计算，几何与绘制必须复用同一来源，不分别猜尺寸。

- `tags` 有 3 个字段：外框约 114px 高，第三行后只有 4px 底部内边距，不出现额外四五行空白。
- `order_items` 有 6 个字段：约 186px 高。
- 有 8 个字段的表：约 234px 高，不显示无意义的滚动条或长表页脚。
- 有 30 个字段的表：约 256px 高，内部同时可见 8 行，页脚显示 `1–8 / 30 个字段`；滚动到底显示 `23–30 / 30 个字段`。
- 加载成功但没有字段：表头下显示一个 24px 的“暂无可见字段”状态行。

以上是紧凑卡片，不是每个节点必须长成同高的表单面板。

### 4.2 字段行：三列而非拼接字符串

横向布局从左到右为：状态图标槽、字段名称、字段类型。

- 左右 padding 10px。
- 图标槽宽 14px，其后 6px 间距。主键使用 key 图标，外键使用 link/relationship 类现有图标；普通字段图标槽留空，不再给每行加灰圆点。
- 同时是主键和外键时优先显示主键图标，并在 tooltip 中写清“主键、外键”。外键信息未加载时不要推测 FK。
- 中间字段名占剩余空间，正常文字色、单行省略，不能因为类型很长而缩成零宽度。
- 右侧类型列固定约 88px，右对齐、弱化颜色，与字段名间隔 8px，超出单行省略。tooltip 展示完整字段名、类型和已知约束。
- 示例：左侧 key 图标，中间 `customer_id`，右侧 `bigint`。另一行中间 `description`，右侧 `varchar(1024)`。类型列右边缘始终对齐。
- 名称、类型以独立展示数据缓存，不能继续使用 `"字段名  类型"` 一个字符串。
- 主键图标可用 UiColors 中的语义强调色；不要在节点函数里直接写 RGB，也不要把整行染成高饱和颜色。
- 默认不画重横线；行 hover 时使用轻微背景色。不要为实现 hover 每次重建全库场景。

### 4.3 长表滚动

- 先核查 gpui-component 0.6.0 的虚拟列表、ScrollHandle、Scrollbar 及项目已有封装，复用合适机制。
- 超过 8 行才启用内部滚动。使用固定高度字段视口，展示可见字段及必要 overscan，不创建全部字段行。
- 悬停或滚动时可见细滚动条；仍可通过键盘焦点、方向键/PageUp/PageDown 查看完整字段。交互与列表默认行为一致。
- 字段区滚轮用于字段滚动，不能同时平移画布或触发邻域展开。滚动方向遵循平台和 GPUI 现有惯例。
- 不采用“每次滚轮累加行数，再转整数切片”的粗糙实现；高精度触控板应流畅。
- 滚动到顶部/底部时不继续更新状态制造无效重绘。
- 按 tab 与稳定表身份保存滚动位置，离开视口再进入后恢复。
- 刷新后字段变少，必须 clamp 偏移，不能发生切片越界或永久空白。
- 若确实没有适用组件，先记录已检查的组件与不适用原因，再做最小组合；不要新增一套通用滚动条。

## 5. 稳定布局：槽位和卡片分离

### 5.1 本轮保留有界网格，不引入力导向

网格单元预留最大卡片空间，但预留空间不绘制外框。

- 槽位宽 260px，横向间距 72px；槽位高按最大卡片高度 256px 预留，纵向间距 48px。
- 卡片左上角固定于槽位左上角。已加载短表收短的是外框和内容，后面的槽位不移动。
- 必须接受短表下方有画布留白；这是本轮保留稳定布局的明确取舍。不能为消除这点留白偷偷引入全图重排。
- 初次获得有效视口宽度后确定列数：`max(1, floor((viewport_width - 64 + 72) / (260 + 72)))`，并限制不超过表数。
- 不用固定 5 列，不依赖 960px 之类首帧猜测尺寸决定最终布局。
- 首次布局未完成时先展示明确加载状态；布局确定后再显示节点，避免先显示五列又突然改成三列。
- 后续窗口 resize 只更新裁剪和可见集合，不自动改变列数；用户主动点击“重新排列”才使用新的宽度。
- 稳定排序沿用现有语义。新字段、关系到达不重置 pan、不重新排序。
- 对局部展开中新增的表，保留已有表的位置，新表放入空闲槽位；视图范围被用户明确重置时可重新计算布局。
- 整个数据库仍可访问，不采用前 N 张表截断，不恢复首字母分组。

### 5.2 加载与几何状态

- 未加载/加载中节点：表头下显示 3 行左右的静态骨架条及状态文字，占用约 3 行字段空间；不为每个节点启动独立动画定时器。
- 字段到达后，节点在自己预留的槽位内变为实际高度。允许自身向下增长/收短，不移动其他节点。
- 失败节点：紧凑状态行和组件重试入口，不能伪装成“无字段”；重试不清空其他节点。
- 查询索引可先用固定槽位做粗筛，再按真实卡片矩形精筛；节点绘制、点击命中必须使用真实卡片高度。
- 不把字段数变化作为重新生成全图坐标的理由；只更新受影响的展示数据和必要索引。

## 6. 连线：明确的表级圆角折线

本轮采用表级关系端口。不要画在某一字段行旁，造成“此线连接这个字段”的误解。字段级连接、字段离屏后的端口映射另做专项。

### 6.1 端口与路径

- 端口位于表头区域的左右边界，y 为强调条下的表头中点，位置不随字段数量和内部滚动变化。
- 普通线宽 1px；选中关联线宽约 1.5px。颜色使用 UiColors，普通边弱于文字但必须能看见。
- 端点为约 4px 的小空心圆；同一端口多关系可共享端点，关系本身不能从数据中删除。
- 采用水平/垂直折线，拐角圆角半径约 6px。先从端口向外走 16px，再进入槽位之间的走线通道，最后接入目标端口。
- 用网格的行间、列间空隙布线，不让路径直接穿过其他卡片正文。
- 同排非相邻表需要绕经行间通道，不能沿表头高度穿过中间节点。
- 同列上下表走该列一侧的通道；自关联从卡片一侧绕出形成可见小回路，不能退化成零长度线。
- 多条边共享通道时采用稳定顺序及有界偏移；避免重合成一条无法区分的粗线，也不能随每帧重新随机分配路径。
- 密集关系允许部分路径重叠，靠选择高亮识别；不承诺通用无交叉自动布线，不隐藏或截断关系。

### 6.2 与虚拟化、性能的关系

- 当前 ErEdge 只存两个端点、查询检测直线；改成折线后，必须同步更新路径数据、包围盒、索引与相交判定。
- 使用实际折线段/圆角的保守包围范围筛选，必要时精筛；不允许因仍检测旧直线而漏掉可见折线。
- 两个节点都在屏外、折线路径经过视口时仍绘制；实际折线路径不经过视口时不要仅因旧端点直线相交而构建路径。
- 路由在布局/关系变化时预计算，平移只做坐标变换和可见查询；禁止每次鼠标移动重新布局/寻路。
- 不能为了连线好看对每条边扫描全部节点。利用已有网格通道和索引，先测量大图构建与平移成本。

### 6.3 关系语义

- 不凭外键就标注 1:1、必选关系或完整乌鸦脚基数。无法可靠取得唯一性/可空性时，保留中性的表级连线。
- tooltip/详情至少能展示已有来源表、字段与目标表、字段。复合关系不能只展示其中一个字段却称之为完整关系。
- 沿用现有真实关系数据，本轮不重新定义外键或逻辑关系模型。

## 7. 选择与交互

- 点击表头选择表；卡片增加主题强调色轮廓，不改变尺寸或布局。
- 选中后与该表直接相关的连线高亮，其他边保持较弱可见；点击画布空白或 Esc 取消选择。
- 选中不触发数据库重读，也不应让字段滚动位置复位。
- 当前局部 ER 若原来“点击整个节点即展开邻域”，本轮改为选中，并在表头右侧提供明确的“展开关联”图标按钮。保留既有展开能力，按钮提供 tooltip、hover 和 loading/disabled。
- 内部字段滚动、滚动条拖拽、重试按钮、展开按钮不能穿透成画布拖动或误触其他操作。
- 表头与操作按钮支持合理焦点和键盘激活。tooltip、按钮和菜单复用已有组件。
- 保留空白处按住平移；画布外松开、失焦、切换/关闭标签后正确清理拖动状态。

## 9. 自动验证

- 按 AGENTS.md 执行 cargo fmt、cargo check 和相关测试；修改 app/core 逻辑运行对应测试。
- 3、6、8、30 字段卡片的实际高度、滚动范围和可见行正确；边框不会保留固定空白。
- 字段加载前后，同表槽位左上角、其他表坐标、pan 保持不变；短卡片外的空白不可误命中该表。
- 刷新后字段减少、变零、失败时滚动偏移安全，不能数组越界。
- 内部滚动位置在虚拟化移出/移入后恢复，方向与现有组件一致。
- 真实生产布局在首次、空图、resize 后都有非零尺寸。不要只手工复制一个 Taffy 树来宣称覆盖生产回归。
- 折线查询覆盖屏外两端穿越、端点直线与实际折线路径不同、自关联、并行边、同排隔表与边界接触。
- 主题切换后缓存颜色正确更新；图/关系变化后路由缓存正确失效。
- 50、200、1843、10000 表均无截断；大表字段区只创建可见行；预计算和索引内存有界。
- 对同一构建配置、数据规模、视口进行修改前后比较；不要把 CPU 纯函数计时当作完整 UI 帧耗时。
- 主动检查当前鼠标更新是否引起无必要的全主窗口渲染，避免视觉修改导致已解决的卡顿重新出现。

## 10. 用户配合验收：禁止依赖截图识别

Claude Code 无法识别图片。不要截图、调用截图工具、要求用户上传截图，也不要假装已经视觉验收。

先完成代码和自动验证，再给出新程序的准确启动命令，提醒旧实例退出以免命中单实例守卫误测旧版本。由用户按以下文字步骤验收：

1. 打开包含 3 字段短表和超过 8 字段长表的 ER。短表外框包住内容，长表有滚动条与总数提示。
2. 检查字段名左对齐、类型右对齐，主外键图标清楚，长文本悬停可完整阅读。
3. 滚动长表，确认最后一个字段可达，画布不跟着动；移出视口再移回来，滚动位置保留。
4. 首次字段逐步到达时，其他表不移动；窗口 resize 不重新排列，点击“重新排列”后才采用新宽度。
5. 检查关系线不直接横穿中间卡片；点击表头时只高亮相关线，Esc 取消；局部“展开关联”按钮仍可用。
6. 切换明暗主题，文字、边框、连线可辨；切换/关闭标签后无残留拖动。
7. 在大库连续平移约 10 秒，由用户反馈流畅度和 FPS/FRAME/P95 的文字读数。

用户可只回复各项“通过”或异常描述。日志和程序能读取的指标由实现者自行收集，不把这部分工作转给用户。

交付区分自动测试通过、用户手动通过、尚未验证。未实测的平台明确列出；启动成功或命中单实例守卫不等同于 ER 页面验证成功。
