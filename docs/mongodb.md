# MongoDB 支持

> 适用范围：FluxDB Desktop（macOS / Linux / Windows）
>
> 交互语义对齐 MongoDB Compass，架构不复用其 Electron/React 实现。

## 1. 连接

### 1.1 表单

连接对话框选择 `MongoDB` 后，**连接串导入行位于表单最上方**（主入口）：

- 粘贴 `mongodb://` 或 `mongodb+srv://` 连接串 → 点「导入」→ 自动回填主机、端口、SRV、用户名、密码、默认库、认证库。
- 末尾没有 `/默认库` 也能解析（`mongodb+srv://user:pass@cluster0.xxx.mongodb.net` 合法）。
- 用户名/密码支持百分号编码（`p%40ss` → `p@ss`）。
- `authSource` 与白名单参数（`retryWrites`、`readPreference`、`maxPoolSize` 等）原样保留；未知参数在导入时**报错而不是静默丢弃**。
- 密码只进内存与加密存储，不写配置文件、不写日志。

表单其余字段：主机/端口、SRV 开关、用户名、密码、默认库、认证库、认证方式。

### 1.2 连接右键菜单

打开连接 / 创建数据库 / 关闭连接 / 编辑连接 / 删除链接 / 复制链接 / 刷新 / 显示连接信息 / 查看性能指标（当前置灰）。

「显示连接信息」按 Compass 展示：拓扑类型、版本、主机列表、可见数据库。

### 1.3 库右键菜单

创建集合 / 删除数据库 / 命令行终端 / 刷新。

「创建数据库」要求同时填写**库名与首个集合名**：MongoDB 的库由首个集合隐式创建，只有库名会得到一个不存在的空库，因此连接器直接拒绝空集合名。

「创建集合」成功后由界面主动重取该库的子节点（控制器只替换第一层库列表），新集合立刻出现在「集合」分组里，无需手动刷新；同时保留用户对该库的展开态。

## 2. 浏览

树层级：连接 → 库 → 「集合」分组 → 集合 / 视图。

- 集合点击打开集合工作台；视图同样打开，但标记只读（隐藏全部写入入口）。
- 集合分组默认折叠，首次展开时懒加载集合列表。
- 集合行图标为 `tree/collection.svg`（层叠文档），与关系型「表」图标区分；视图沿用 `tree/view.svg`。
- 集合工作台标签参与侧边栏选中联动：当前活动集合标签时，侧边栏对应集合行、所属库与分组都显示选中态，与表标签行为一致。

## 3. 集合工作台

四个分节页签：文档 / 聚合 / 索引 / 信息。页内不再重复「库/集合」命名空间条——标签页标题已是「库/集合」，再画一行只是重复信息、白占 30px；只读标记移到分节页签行右侧，避免随命名空间条一起消失。

- **文档**：筛选、投影、排序、排序规则、起始、条数、执行上限、索引提示，分页；三种展示方式（卡片 / 表格 / JSON）。三种方式都只读渲染，不访问数据库。
- **查询面板**：一张卡片四段——首行常驻、条件构建、更多选项、高级查询。
	- 卡片：`panel_bg` 底色 + 1px 描边 + 11px 圆角 + 一层极淡投影，内容裁在圆角内（`overflow_hidden`）。查询区与结果区因此是两个视觉层级，而不是一堆控件直接铺在页面上；卡片外只有 12px 内边距，不叠第二道分隔线。
	- 首行只有 Filter 一个输入框，占满剩余宽度；右侧依次是「重置」「查询」「更多选项」，顺序与 Compass 的 Reset → Find → Options 一致——清空在主操作左边，展开控件收最右，主色按钮不与它相邻。层级分三档：查询是实心主色按钮（下限 90px），重置是描边图标按钮（`reset-button` 只留图标，文案挂 tooltip 与无障碍标签），更多选项是无框纯文字 + 箭头（`ghost`），展开时换绿底绿字绿描边。查询在途时「查询」与「重置」置灰，避免连发。
	- 高度分三档：Filter 一行 36px（`MONGO_QUERY_FILTER_HEIGHT`）、三个操作按钮 28px（`MONGO_QUERY_ACTION_HEIGHT`）、附加条件格子 32px（`MONGO_QUERY_CONTROL_HEIGHT`），共用同一条行中线。附加格子不带主入口的分量，字号 11px、行高 16.5px，压到 32px 刚好让字形仍在框中线上——纵向空间要留给下面的结果区。Filter 那 36px 是 `1 + 8 + 18 + 8 + 1`（描边 + 上下内边距 + 行高），34px 量的是内容区，取 36 才不会把最后一行的底部裁掉 2px；按钮没有这层约束，跟着做到同高只会又粗又笨；三个按钮之间必须等高，否则读成三块拼凑的控件。首行内边距 6px 8px（原 8px）：这一行只有 36px 控件，8px 上下留白白占 4px。
	- **Filter 回车增行，封顶 4 行**（对齐 Compass）：每多一行整条首行长高 18px，第 5 行起高度固定、由编辑器自己滚动（带滚动条与滚轮）。
		- 不能直接用 `auto_grow`：那是 `TextareaState` 独有的模式，且在 `gpui-base` 里是 crate 内 API；Filter 必须留在 `EditorState` 上，补全只挂在它那里。
		- 所以行数由视图数换行符推出（`mongo_query_filter_rows`，按 `\n` 切而不是 `str::lines`——末尾换行后那行也算一行，否则光标停在空行时框会矮一行），框高按 `MONGO_QUERY_FILTER_HEIGHT + (行数 - 1) × 18` 算。不折行（`soft_wrap(false)`），所以行数只由换行决定。
		- 编辑器本体被钉成内容区高度（外框高度减上下 1px 描边），超出的行由编辑器自己滚，而不是被 `overflow_hidden` 裁掉——裁掉的话光标能跑到看不见的地方。
		- 面板是独立实体：打字只重绘编辑器，面板不会自动重算高度。`MongoQueryInputs` 观察 Filter，只在行数**跨档**时通知面板。逐键通知会把侧栏树/标签条/文档列表一起多排一帧，正是「打开条件构建后掉帧」的来源。
	- Filter 是「描边外框 + 内嵌定宽标签 + 无边编辑器」：标签列 84px、10px 等宽字体、薄荷底+ 右侧分隔线；输入区 12px 等宽（查询语句是 JSON 片段，等宽才对得齐括号）。
		- 外框接管焦点态：聚焦时描边切成强调线（浅色 `#111111` / 深色 `#8ab4ff`），未聚焦悬停时深一档。编辑器本身关掉了 `appearance` / `focus_bordered`，不自带描边，所以焦点态必须由外框补上，否则点进输入框后整块毫无变化。
		- **铭牌与输入区直接挂在外框上**：外框不再给内容包一层 `flex_1` 容器。那层容器会让铭牌和输入区变成两个等分的兄弟——铭牌只占自身宽度、剩下的空白留在输入区左边，`{}` 就飘到整行正中（截图里的那条毛病）。外框本身是 `items_center` 的横向 flex，铭牌 `flex_none`、输入区 `flex_1`，一个兄弟层级就够。
	- 默认**只占一行**：日常改过滤条件时查询区不长期挤占结果空间。用户没点过「更多选项」时，若已生效查询填过任一附加条件则默认展开——条件生效了却藏在收起的面板里，用户会以为没生效。
	- **「更多选项」只有一行**：`[条件构建 | 投影 | 排序 | 返回条数 110px | 高级查询 ▾]`，间距 8px、内边距 7px 12px、薄荷底，与首行用一条细分隔线切开，读作「同一张卡片里的第二段」而非另起一块。
		- **名称塞进框内铭牌**（`mongo_query_cell_label`），不再用「标签在上、输入在下」的格子：标签行会给每个格子白加一条 ~19px 的横向带，四格叠起来整块逼近结果区的高度。铭牌与 Filter 的 `Filter` 标签同一套写法（框内左侧、右侧分隔线、薄荷底），但字号 10px、颜色 `muted`——附加格子不是主入口，名称不该抢 Filter 的注意力。对象格的铭牌右端顺带放 `可选`；数字格的边界与单位（`1–500`、`ms`）走悬停提示——数字格本来就窄，铭牌里再塞一段边界文字会把输入区挤到看不见。
		- **数字格的字要自己竖直居中**：单行 `Input` 在 `request_layout` 里自建 `Style`、高度只认自己的行高（`h_6` + 上下 2px 内边距），外面给的 `h_full` 进不去。所以数字格把 `Input` 包在一层 `h_full + items_center` 的 `div` 里，否则 32px 的格子里 16px 高的输入段贴顶，`0` 的基线明显高于铭牌文字。对象格子用的是多行编辑器，它本来就吃 `h_full`，不需要这一层。布局测试用 `mongo-query-number-body:<field>` 量这层与整格的中心差。
		- 数字格是定宽：返回条数与起始位置 110px、执行上限 110px（`MONGO_QUERY_NUMBER_WIDTH` / `MONGO_QUERY_POSITION_WIDTH` / `MONGO_QUERY_MAX_TIME_WIDTH`）。名称挂在铭牌里后这几格只剩名称一个变量，宽度不再被标签行撑开。
		- 条件构建入口与「高级查询」都是无框 ghost 文字按钮 + 图标，与首行的「更多选项」同一档视觉权重，展开时绿底绿字。这两处不再用描边大方块按钮：那一行已经全是输入框，再加实心/描边控件会把整行重心拖到左边，也白占一格宽度。
		- 条件行内部按 `1 : 150px : 1.35` 分配：字段格与值格都用 `flex_1`（`flex-basis: 0`）从相同的零基数起算。按内容算基数时字段格里的 `w_full` 会以整行宽度作基准，把值格挤成一条缝——那正是「值输入框为什么这么小」的成因。
		- 输入框**下方与上方都不再有说明文字**：帮助文本一旦出现，八个格子就是八行小字，密度压过条件本身。对象格按 1 份伸缩，数字格定宽。
	- **「高级查询」入口挂在首层那一行的末尾**，不再单独占一行——那一行只放一个 10px 文字按钮，收起时白花一条 ~26px 的横向带。展开后 `[排序规则 | 起始位置 110px | 索引提示 | 执行上限 110px]` 排成一行，与上层用**虚线**分隔（`border-top: 1px dashed`）——虚线是「同一组里更细的一层」，换成实线会和上面那条分隔线抢同等分量。对象格按 1.5 份伸缩。
		- 不做成带框按钮：这已是卡片内第三层控件，再加带框按钮会和「更多选项」抢同一档视觉权重。收起首层时第二层一并收起，避免下次展开常用项时低频参数跟着弹出来。
	- **收起态有角标**：哪一层的格子看不见，哪一层的入口就给计数——条件还在生效，不能悄无声息地藏起来。两层都收起时「更多选项」右侧显示两层条件总和（`mongo-query-option-count`）；首层展开、第二层收起时，「高级查询」自己显示 `mongo-query-advanced-count`。展开的那层不显示，避免和可见内容重复。
	- 展开态按标签页分别记忆（`mongo_query_options_expanded` / `mongo_query_advanced_expanded`），关标签页即释放；首次点击前不落盘，避免默认态被一次误点永久改写。

### 条件构建

图形化改 Filter 的入口，不是第二个筛选项——它是 Filter 的另一种输入法。

- **只有一份查询文本**：构建器的每次改动立刻把 `JSON.stringify` 结果写回 Filter 编辑器，执行时读的仍是那一份文本。构建器不持有独立查询状态，因此永远不会出现「构建器里一套、真正查的是另一套」。
- **反向解析接受 Compass 的宽松写法**：先按严格 JSON 解析，失败再按 JSON5 收（无引号键、单引号、注释、尾逗号），规则与连接器执行查询时一致。否则会出现「`{event_type: "page_view"}` 能查、构建器却报语法错」——同一份文本，两个入口两种结论。先试严格 JSON 是必须的：JSON5 把所有数字读成 f64，`{"age": 41}` 会落成 Double，写回时那一位就悄悄改了类型。`NaN` / `Infinity` 直接拒——serde_json 会把它读成 `null`，等于把条件换成「等于 null」。
- **只认能无损表达的形态**：解析成功后只接受平铺对象里「字段 → 标量」或「字段 → 单个受支持 `$运算符`」。`$or`、`$regex`、嵌套对象、多运算符组合、数组等值一律**拒绝并提示继续手写 JSON**，Filter 一个字都不动——猜错语义去改写，比不做更糟。提示直接显示在条件行位置的同一行（红字），不会只弹个无声的失败。
- **运算符八种**：等于 / 不等于 / 大于 / 大于等于 / 小于 / 小于等于 / 包含任一 / 字段存在，下拉里显示成 `等于 · =`、`不等于 · $ne` 这样带符号的形式。`$exists` 的值恒为布尔，值输入框随之禁用。
	- **下拉用 `Anchor::TopLeft` 向下弹**：本库的 `BottomLeft` 指「弹层底边贴触发器顶边」，是向上弹。条件行上面是 Filter、下面是结果区，向上弹会盖住刚编好的字段格与值格。字段目录与运算符两处下拉都取 `TopLeft`。
- **值的类型推断**（`mongo_builder_condition_value`）：`true`/`false`/`null`/整数/小数原样，带引号的去掉引号，其余按字符串；`$in` 按逗号拆成数组。空值行直接跳过（`$exists` 除外）——加了一行还没填值时，不该出现 `{ "field": "" }` 这种把结果查空的过滤条件。
- **往返不丢类型**：JSON 标量回填输入框时**保留引号**（`"500"` 不会变成 500）。丢引号会让一次展开/收起把字符串字段悄悄改成数字匹配。
- **行结构**：`IF/AND | 字段 | 运算符 | 值 | 移除`。第一行写 `IF`（透明底），其余写 `AND`（绿色浅底 + 绿描边），与「所有条件需同时满足（AND）」的语义一致；最多 6 行，到顶后「添加条件」置灰。新行创建后焦点落在值输入框。
	- **没有列名行**：字段格自己的占位符写「字段路径，如 customer.tier」，运算符直接显示「等于 · =」，值格写「值，如 "paid" 或 500」——三列各自说清楚是什么，再挂一条列名行就是重复，还白吃掉一条 ~14px 的横向带。
	- **「添加条件」跟着最后一个条件行走**，不单独占一行：末行的条件行吃掉剩余宽度，右侧接「添加条件」与快捷键提示；没有条件行时它就是与空提示同一行。整块内边距 8px 12px、行距 6px，高度只有条件行本身。
- **字段格**是输入框而不是固定下拉：集合里没采到的字段也要能写。字段目录（补全用的 `field_catalog`）非空时，格子右侧多一个箭头，展开按路径选。目录为空时退化成纯输入。字段候选整块用 `Rc<[SharedString]>` 共享给所有行，不按行克隆——目录越大（实测 52 字段）逐行克隆越贵。
- **字段格与值格都挂补全**（`configure_mongo_builder_completion`）：两格因此用 `EditorState` 而不是单行 `InputState`——只有编辑器有 `Lsp.completion_provider` 这个入口。渲染走 `mongo_query_editor_body`（与 Filter 同一套外壳），格子高度仍是 `MONGO_QUERY_BUILDER_CONTROL_HEIGHT`（30px）。
	- **字段格补路径、值格补该字段出现过的取值**。值格的候选按**同一行的字段格**去查（值格持有字段格的 `WeakEntity<EditorState>`），不是全局词表：全局词表会让 `status` 冒出文档里任何位置出现过的手机号、订单号。
	- 两格都不是 JSON 片段，所以不走 `mongo_completions` 的语法扫描（那套按键位/值位分候选，裸文本会被一律当值位）。`mongo_builder_completions` 直接按「字段格 / 值格」分两支：字段格插裸路径（不加引号、不补冒号）；值格若用户已敲开引号，只替换引号里那截词并补回收尾引号。
	- 编辑器默认 reserve 两行（`LayoutMode::CodeEditor` 的 `rows = 2`，编辑器没有对外改行的入口），布局高度因此比 30px 的格子高；外壳用 `overflow_hidden` 裁掉多出的部分，首行仍从格子顶边开始。布局测试量的是「盒子顶边贴住格子顶边」，不是盒子中心对格子中心。
	- `soft_wrap(false)` + `submit_on_enter(true)`：不折行，回车只结束编辑、不往条件格里塞换行。
	- 打字补全与右侧箭头并存：箭头用来**浏览**整个目录，打字用来**过滤**。
	- 值格 `$exists` 时仍禁用（`Editor::disabled`），不参与补全。
- **重绘范围**：`sync_mongo_query_builder` 每次按键都会执行（写回 Filter + 清错误提示），**只在错误提示真的消失时**才 `cx.notify()` 本视图。条件行与 Filter 都是独立实体，各自 notify 足以重绘自己；无条件 NOTIFY 会让整个主视图（侧栏树、标签条、文档虚拟列表、查询面板）每次按键多排一帧，正是「打开条件构建器后帧率持续下降」的来源。
- **末行**：`添加条件`（绿色文字 + 加号）、右对齐的 `⌘ ↵ 执行查询` 键帽提示。AND 说明已去掉——`IF/AND` 标签本身就说清楚了，那句注释只是把同一件事再说一遍。快捷键真的可用：`execute_or_apply` 增加了 `TabKind::MongoCollection` 分支，只在文档分节执行（聚合分节有自己的管道与运行按钮）。
- **展开态与「更多选项」绑定**：构建器入口在那张网格里，网格收起时构建器一并收起（`toggle_mongo_query_options` 同时清掉构建器展开态），否则入口不见了、面板还留着。构建器的行状态按标签页缓存（`mongo_query_builders`），切走再切回来不丢草稿；关标签页释放。
- **起始位置只有一份**：`skip` 同时是分页偏移与请求的 `skip`。翻页按钮把新偏移写回面板这一格（`set_mongo_offset`），手填起点也直接生效；`LoadMongoDocuments` 以草稿的 `skip` 为准更新 `Pagination`，`SetMongoOffset` 同时写回 `applied_query.skip`。两边各存一份的话，手填过 skip 再翻页会互相覆盖。清空这一格即「从头查」，不回落上一页偏移。
	- **执行上限（Max Time MS）**：对应驱动的 `max_time`。留空或填 `0` 都按「不限制」落地（`max_time_ms: None`）——服务器对 `maxTimeMS: 0` 的语义是**立即超时**，那不是用户清空这一格的本意。
	- **排序规则（Collation）**：Extended JSON 对象，直接交给驱动的 `Collation` 反序列化（`mongo_parse_collation`），不自己逐字段翻译——字段与 wire protocol 一一对应，手写映射只会漏字段、也容易把拼写错误吞成默认值。`locale` 必填，缺失时明确报 `Collation 无法识别（locale 必填）`。
	- **索引提示（Index Hint）**：接受索引名字符串（`"_id_"`）或键定义对象（`{ "age": 1 }`），对应驱动的 `Hint::Name` / `Hint::Keys`。空对象当「没填」会把用户的明确输入吞掉，因此直接报错。
	- 解析与校验都在连接器的 `mongo_find` 里做（`mongo_parse_collation` / `mongo_parse_hint`），UI 只负责收集文本：与 filter/projection/sort 一样，空文本等价于未提供。
	- **条数的来源与上限**：初值取设置 →「编辑器」→「默认查询限制」（`settings.page_size`，档位 不限制/100/500/1000），不是数据表页大小。归一化在 `fluxdb_app::mongo_query_limit`：`0`（不限制）与超过连接器硬上限（`fluxdb_core::MONGO_MAX_DOCUMENTS_PER_QUERY` = 500）的档位都按 500 落地。输入框用 `InputState::validate` 只接受 `1..=500` 的纯数字，超上限的按键直接被拒；`MongoQueryDraft::to_request` 与 `LoadMongoDocuments` 再各夹一次，覆盖 AI/恢复等绕过输入框的路径。三处共用同一个上限常数——填得进去的值必须原样生效，否则「填 1000 只返回 500 条」看起来像丢了数据。
	- 「重置」清空投影/排序/排序规则/索引提示与执行上限、起始回 `0`、Filter 回 `{}`、条数回当前生效页大小（无标签页状态时回设置里的默认查询限制），并立即重查；不因条件是否变更而置灰（输入框是独立实体，父视图不随输入重绘，按变更态置灰会停在上一帧）。
	- **查询条件接受宽松 JSON**（与 Compass 查询栏一致）：`{ age: 41 }`、单引号、注释、尾逗号都能跑。解析走 `mongo_parse_json`：先试严格 JSON，失败才退到 JSON5。先试严格不是图省事——JSON5 把所有数字读成 f64，`{"age": 41}` 会落成 BSON Double 而匹配不到存成 Int32 的字段。`NaN` / `Infinity` 直接报错：JSON5 会把它静默读成 `null`，等于把查询条件悄悄换掉。
		- 宽松解析**只用于查询入口**（filter / projection / sort / collation / hint / 聚合管道，都是只读）。写文档、写命令的入口仍只认严格 JSON（`mongo_parse_object`）：写入路径放宽解析会把 `{ age: 41 }` 这种"看起来能跑"的写法变成一次真实的脏写。
- **结果条**：左侧三种展示方式页签 + 条数统计，右侧「新增文档」（`+`）、「导入文档」（文件夹输入图标）、刷新（只读对象只显示刷新）。三个按钮都用卡片头同款 24px 无边框图标按钮——结果条只有 38px 高、旁边是 11px 统计文字，通用 30px 描边按钮在这行里显得过大。查询在途时刷新图标自身旋转（按钮同时降为不可用样式、点击被吞掉防连点），不另换 spinner 图形。
- **卡片**：与 Compass 一致，正文是字段列表而不是整段 JSON。卡片头的折叠 / 编辑 / 复制文档 / 复制 / 删除用 24px 无边框图标按钮（`.document-head .icon-button`），复用通用 30px 描边工具栏按钮会顶满 30px 的卡片头。每张卡片可整体折叠（**整条卡头都可点**，箭头只是入口之一；点操作按钮不会连带折叠），嵌套对象/数组默认收起为 `{ N fields }` / `[ N items ]`，点开后才展开子行（数组下标写 `[i]`）。折叠与展开按标签页记忆，卡片身份优先用 `_id`，缺失时退回页内下标。
	- **四个操作按钮（文档 / 表格 / JSON 三处一致）**：编辑、复制文档、复制到剪贴板、删除。三处共用 `mongo_document_actions`，按钮顺序、可用状态与点击行为必须完全一致，否则换个展示方式就找不到同一个操作。
		- 编辑：打开右侧抽屉（只读对象打开只读详情），已实现（见 §3）。
		- 复制文档：打开右侧抽屉预览并微调副本内容，确认后插入一条新文档（见 §3.3）。只读对象（视图）不渲染该入口。
		- 复制：把当前文档的 Extended JSON 写进剪贴板，成功后弹「已复制文档」提示。写剪贴板本身无声，没有提示用户无法判断是否成功。
		- 删除：弹确认框，确认后按原始 `_id` 删一条，已实现（见 §3.2）。只读对象（视图）不渲染删除入口。
	- **性能边界**：三种展示方式都做了行虚拟化，只构建视口附近的文档。
		- 文档 / JSON 用 `ListState` + `gpui::list`（卡片高度随展开态变化，由列表逐项测量）。折叠、展开嵌套字段、点开 JSON 节点后调用 `ListState::remeasure()`，否则下方卡片仍按旧高度排布。
		- 表格用 `uniform_list`：数据区与右侧固定操作列是两个列表，**共享同一个 `UniformListScrollHandle`**，行高统一所以始终逐行对齐；横向滚动由 `overflow_x_scrollbar` 的元素状态持有，跨帧不掉。
		- 整页文档只解析一次：`MongoPageData`（原始文档 + 解析结果 + 表格行/列）放在 `MongoDocumentCache` 里，逐帧渲染只读，不再每帧 `serde_json::from_str`。缓存只在 `load_generation`、文档条数变化，或**在途期间建的缓存等结果落地后**重建，关标签页时释放。最后一条不能省：`begin_load` 已推进令牌但 `page` 仍是上一页，此时建出的缓存与落地结果可能同令牌同条数、内容却已换，光比前两项会把过期内容当最新（表现为点了「删除第 N 篇」却删了别的文档）。
		- 卡片正文仍只在展开时构建：收起状态不建字段行、不跑 `build_pretty`。字段行渲染前已按文档缓存主题色，不逐行重复构造。
		- **尚未虚拟化的两处**：聚合结果列表（`mongo_aggregation_section`）与右侧详情抽屉（`mongo_inspector`）仍逐帧构造 `JsonComponent`。默认聚合管道只返回一行统计，影响有限；若聚合结果返回大量文档，需要按同一套缓存 + 虚拟列表处理。
- **JSON**：与 Compass 一致，仍是**逐条文档卡片**（卡头同文档视图），正文是该文档格式化后的整篇 JSON：左侧行号列（31px 右对齐、9px 弱化色）+ 折叠箭头，正文按 token 着色，object / array 可逐层折叠成 `{ … }` / `[ … ]`。
	- 默认态与 Compass 一致：**根节点展开、嵌套的 object / array 全部收起**（显示为 `{ … }` / `[ … ]`），点箭头才逐层展开。
	- 折叠不是卡片自造的能力：行拆分、折叠占位、折叠后行号重建都走 `json_editor` 的 `build_pretty` + `json_fold_view`（同一套渲染器也服务 Redis JSON 面板），卡片只负责持有「本文档被用户点开过哪些节点」（`BTreeMap<TabId, BTreeSet<String>>`，键为 `{文档身份}\u{1e}{路径}`，按标签页记忆）。
		- 存的是**与默认态相反**的节点，所以空集合就是完整默认态，不需要为每篇文档预置折叠集合。
		- 折叠状态按**文档身份**记录而不是行号，翻页/刷新后同一文档仍是同一份折叠；非法 JSON 退回纯文本。
- **表格**：对齐 Compass。行号列 + 每个顶层字段一列，列头是「字段名 + BSON 类型」（`_id ObjectId`），列序按字段在文档中首次出现的顺序（不按字母排），缺字段的单元格显示 `—`。单元格定宽 180px、单行省略，超过约 26 字符挂悬停提示显示全文。嵌套值在单元格里显示 `{ N fields }` / `[ N items ]`，不在表格里展开。
	- **固定操作列**：最右侧 116px 的操作列放在横向滚动区**之外**，字段一多需要左右拖动时编辑/删除入口仍然固定在原地。每一行与数据行同高同序；纵向滚动由数据区与操作列两个 `uniform_list` 共享同一个 `UniformListScrollHandle` 承担，行高统一，两列因此始终逐行对齐。
- **聚合**：Extended JSON 数组形式的管道，结果沿用文档页的三种展示。管道输入区与查询三框一样是可补全的代码编辑器（多行、软换行）。
- **索引**：名称、键、唯一/稀疏等属性。
- **信息**：集合类型、文档数、存储大小等。

### 查询补全（对齐 Compass）

Filter / 投影 / 排序三框与聚合管道都从单行 `InputState` 换成 `EditorState`：只有代码编辑器能挂 `Lsp.completion_provider`，单行输入框没有这个入口。外观仍由外框接管（`Editor::new(..).appearance(false).bordered(false)`），开关只有软换行——查询框关、管道开。

- **位置判定**（`mongo_completion_site`）：在纯文本上扫一遍括号栈与字符串状态，得到「键位 / 值位 / 字符串内值位 / stage 键位 / stage 内键位 / `$` 字段引用」。不用 tree-sitter：输入的是**不完整**的 JSON 片段，容错解析拿到的错误节点反而更难判定。
- **候选来源**：
	- 键位 → 字段路径（带 BSON 类型作说明）+ 查询运算符；聚合 stage 键位 → stage 名 + 聚合/累加器运算符。
	- 值位 → Extended JSON 构造器模板（`{"$oid": ""}`、`{"$date": ""}` …）。**不给 `ObjectId("…")` 这类 shell 写法**：连接器用 JSON + `Bson::try_from` 解析，shell 写法会直接报解析错误，补进去等于制造一次失败查询。
	- 字符串内的值 → **该字段自己**出现过的取值。位置判定扫括号栈时会把每层的键记下来（`MongoFrame::Object { key }`），值位拼出点分路径（`{"status": "pai` → `status`）后按路径查字段表。**不能做成全局词表**：那样写 `status` 时会冒出文档里任何位置出现过的手机号、订单号，一屏错误候选。
	- 聚合 stage 字符串里以 `$` 开头 → 字段引用（`"$status"`）。
- **转义**：不含特殊字符的字段路径原样插入；含点/空格/中文的按 JSON 字符串加引号（`"address.city"`）。键位一律补到值位为止——字符串外 `"$gt": `，字符串内 `$gt": `（用户已经敲了开引号，只补名字、收尾引号和冒号），两种情况都不会写出 `""$gt""`。
- **字段表**（`fluxdb_app::MongoFieldCatalog`）：采集两路来源，都落进标签页状态的 `field_catalog`。
	- 当前页文档：查询结果回写时并入，抽样还没回来也能补全眼前这页的字段。
	- 抽样：`AppCommand::LoadMongoFieldSample` 在打开集合页时跑一次，连接器用 `$sample`（`MONGO_FIELD_SAMPLE_SIZE` = 1000，`secondaryPreferred`，对齐 Compass 的 schema 采样）取文档后摊平成点分路径。
	- 摊平规则：对象按键展开（`$` 开头的键是操作符，跳过），数组按同路径展开元素（只递归对象/数组元素，标量元素只记取值、不参与类型，否则 `tags` 会被记成 `Array | String`），Extended JSON 单键包装（`{"$oid": …}`）记成 `ObjectId` 叶子。上限：路径段数 4、递归兜底 16（数组元素不增加段数，只用段数挡不住 `[[[[…]]]]`）、字段 300、每字段取值 50 条且长度 ≤ 64。同一路径在不同文档里类型不同时都保留（显示成 `String | Number`）。
	- 抽样失败静默降级：补全仍给运算符与构造器，不为辅助信息在集合页弹错误块。
- **垂直居中**：`EditorState` 恒为多行模式，而 `Input::from_state` 对多行**恒定**加 `Size::Medium` 的 8px 上下内边距（`set_editor_paddings`，外部改不掉），文本因此永远从「内容区顶部 + 8px」起排。三条硬约束叠在一起决定了做法：
	1. 改行高治不了：行高铺满内容区时，上内边距把字形整体压低 8px。
	2. 让编辑器盒子垂直居中也不行：编辑器高度随内容行数变化（实测 `{}` 时就是两行、52px），盒子一居中，首行起点就跟着行数漂。
	3. 用负边距抵掉上内边距，第一行看着对了，但第二行被推出可视区。

	结论是**编辑器顶边贴住内容区顶部**，并由框高兜住居中：首行字形中心 = 顶边 + 8px + 行高/2，与行数无关；更长的内容继续往下排。框高按字号定：Filter 12px（行高 18px）一格 36px（含上下描边），附加格子 11px（行高 16.5px）取 32px，两者都让首行字形落在外框的中线上。Filter 会在 1–4 行之间长高（见上文），超出 4 行的部分改由编辑器自己滚动；附加格子与条件构建格仍是固定高度、超出由 `overflow_hidden` 裁掉。
- **测量陷阱**：调试选择器必须挂在编辑器自己那块盒子上。挂在外层 `h_full` 包裹层上量出来的永远是行高，凡是与文字落点有关的断言都会恒真。

- **与 Compass 的差距**：gpui 的 `insert_completion` 只贴 `text_edit`，没有 snippet 占位符跳转，所以 stage 模板补的是 `"$match": ` 而不是带 Tab 占位的多行骨架；查询历史分组也没有（本应用的历史走 AI/查询历史弹框，不在补全里）。取值补全也与 Compass 不同源：Compass 的 `completeAnyWord` 只补**编辑器里已出现的词**，本应用补的是数据库里该字段的真实取值。

右侧抽屉展示单条文档的 Extended JSON，同一个入口兼任编辑：

- 卡片头的编辑按钮（`AppIcon::Edit`）打开右侧抽屉；抽屉头是「编辑文档 + 关闭」，正文是多行 JSON 编辑器（语法高亮 + 错误行内诊断），底部「取消 / 保存」。
- 编辑模型是**整篇替换**（`replace_one`），不做逐字段编辑：`_id` 是唯一可靠的定位条件，逐字段回写会把 BSON 类型拆开再拼回去，收益不抵复杂度。
	- 定位用文档原始 BSON `_id`，不是界面上可读的 `document.id`（后者可能是格式化后的文本）。
	- `_id` 不可修改：界面保存前校验一次，连接器再拒绝一次。
	- `matched_count == 0` 视为失败（文档已被他人删除），不会谎报保存成功。
- 保存前先格式化并校验 JSON；非法时只提示定位错误，不发写请求。草稿与基线相同（未改动）时保存按钮禁用，直接收起抽屉，避免空写。
- 保存失败保留抽屉与草稿，改完可直接重试；保存成功关闭抽屉并重查本页（整篇替换可能改变字段集合）。
- 视图（只读对象）点击同一按钮只给只读详情抽屉，不进入编辑态；卡片处于选中态时再点该按钮即关闭抽屉。
- 编辑草稿只存在界面的编辑会话里（不写入 `MongoCollectionState`）：取消、切页、关标签即丢弃。抽屉宽度 520px，比只读详情宽一档以留出可读行宽。
- 抽屉头的关闭按钮用卡片头同款 24px 无边框图标按钮：头部只有 38px 高，通用 30px 描边按钮会顶满整条、显得笨重。只读详情抽屉同一档。
- **隐式丢弃要确认**：草稿有未保存改动时点另一张卡片的编辑按钮，先弹确认框（标题「放弃未保存的修改？」，「继续编辑」/「放弃并切换」）。遮罩点击、Esc 与右上角关闭都按「继续编辑」处理，破坏性操作只能由用户显式点按钮触发。抽屉自带的「取消 / 关闭」本来就是明确的丢弃动作，不再追问；切到同一篇文档也不追问。
- 表格行编辑仍不支持（`apply_changes` 返回 `Unsupported`），文档修改统一走这条 JSON 编辑路径。

### 3.1 类型与边界

- 查询结果按 **Relaxed Extended JSON** 呈现，保留 `ObjectId` / `Date` / `Decimal128` 等类型标注。
- 字段行的类型徽标按 BSON 类型显示（`ObjectId` / `Date` / `Decimal128` / `Object` / `Array` / `String` / `Boolean` / `Int32` / `Double` / `Null`）。单键且键名是已知 BSON 包装（`$oid`、`$date`、`$numberDecimal` 等）的值按标量处理，不会误渲染成可展开的一层空对象；`$date` 的 `{ "$numberLong": … }` 规范形式也按 `Date` 显示。
- 单页最多 500 条（`MONGO_MAX_DOCUMENTS_PER_QUERY`），超出由 `has_more` 告知 UI，不静默截断。
- 视图（`CollectionType::View`）与时间序列集合：视图只读；时间序列按普通集合处理（可读可写）。
- 表格视图不支持行内编辑；文档修改走右侧抽屉的 JSON 整篇替换（见 §3）。

### 3.2 删除文档

- 入口是卡片 / 表格行 / JSON 卡片的删除按钮（垃圾桶图标，danger 色）。
- **必须先确认**：确认框写明「删除后无法恢复」并带上 `_id`。遮罩点击、Esc 与右上角关闭都按「取消」处理——破坏性操作只能由用户显式点「删除」。
- 定位用文档原始 BSON `_id`，与整篇替换同一套规则；确认期间翻页/刷新不会删错另一篇。
- `deleted_count == 0` 视为失败（文档已被他人删除），不谎报成功。
- 删除成功：收起右侧抽屉（被删的那篇可能正开着），提示「文档已删除」，并重查本页——删除会改变文档数量与下标。
- 删除失败保留现状并提示原因，用户可重试。
- 只读对象（视图）不渲染删除入口，控制器侧再拒绝一次。

### 3.3 复制文档

- 入口是卡片 / 表格行 / JSON 卡片的「复制文档」按钮（两张纸 + 加号图标）。
- 点击后打开**右侧抽屉**，与编辑共用同一副外壳（520px），内容是从源文档剥掉 `_id` 的副本：
	- 头部图标换成「复制文档」图标，标题「复制为新文档」，副标题写明「源文档 _id：…」——用户不必回头确认复制的是哪一篇。
	- 正文与编辑抽屉是同一个多行 JSON 编辑器（语法高亮 + 行内诊断）。
	- 底栏右侧「取消 / 插入」。非法 JSON 时「插入」禁用并保留行内诊断——不会发出坏写入。
- **为什么与编辑统一**：两者正文都是同一篇文档的 JSON，差别只在落库动作（替换 vs 插入）。两套容器会让用户学两套「打开 / 取消 / 关闭」语义，居中弹框的遮罩还会挡住右侧文档列表，而复制常常需要对照原文档改字段。
- **必须剥掉 `_id`**：`_id` 唯一性由服务端保证，带着源文档的 `_id` 插入必然撞键。新 `_id` 由服务端生成，连接器侧对自带 `_id` 的入参再拒绝一次。
- **字段顺序必须与源文档一致**：剥 `_id` 用 `shift_remove` 而不是 `remove`。`preserve_order` 生效时 `serde_json::Map::remove` 等价于 `swap_remove`，会把最后一个字段搬到 `_id` 的位置，副本字段顺序与卡片对不上，用户会以为复制错了文档。`apps/fluxdb-desktop/Cargo.toml` 显式声明该 feature，避免依赖升级后顺序静默变成字母序。
- BSON 类型标注原样保留（`$date` / `$numberDecimal` / `$oid` 不降级成字符串），这与整篇替换同一规则。
- 插入成功：关闭抽屉、提示「已插入新文档（_id：…）」、重查本页——新文档的排序位置未知（`_id` 由服务端生成），不能靠本地推算。
- 插入失败保留抽屉与草稿，用户改完可直接重试。
- 抽屉自带的「取消 / 关闭」是明确的丢弃动作，不追问；但**已有未保存编辑草稿时点复制**属于隐式切换，先弹与「切换文档」同一个确认框（「继续编辑」/「放弃并切换」）。
- 只读对象（视图）不渲染该入口，控制器侧再拒绝一次。

### 3.4 新增文档

- 入口是结果条右侧的 `+`（只读对象不渲染）。打开的是与编辑 / 复制同一个抽屉，初值只有一个本机生成的 `_id`：
	- 不预填业务字段：新增本来就没有源文档可抄，凭空造字段只会诱导用户留下垃圾数据。
	- `_id` 用 `{"$oid": "…"}` 包装，不能用裸的 24 位十六进制串——后者会被当成字符串 `_id`，与集合里既有的 ObjectId 类型对不上。
	- `_id` 在打开时生成一次并留在草稿里；用户改不改都用它落库，因此插入前就知道新文档的 `_id`，插完可立即拿去查询。
- 生成规则与驱动同构：4 字节秒级时间戳 + 5 字节进程内固定随机数 + 3 字节自增计数（模 2²⁴）。随机种子取自 `RandomState`，不为此引入 `bson` / `rand` 依赖。
- 底栏右侧「取消 / 插入」，非法 JSON 时「插入」禁用。插入成功关闭抽屉、提示「已插入新文档（_id：…）」、重查本页；失败保留草稿。
- **连接器侧的 `_id` 校验**：允许省略（复制路径，由服务端生成），允许显式给 ObjectId（新增路径），其它类型拒绝并说明——那多半是把 `_id` 当成普通字段误填。

### 3.5 导入文档

- 入口是结果条 `+` 之后的文件夹输入图标（只读对象不渲染）。弹窗与表数据导入共用同一副外壳与文案骨架，同样是「常规 / 消息日志」两个页签。
- **消息日志**：点「开始导入」后自动切到日志页；每批进度追加一行（阶段 + 文案 + 相对开始的耗时），收尾写「完成」或「失败」行，失败明细按 `report.errors` 逐条落成失败行。日志页底部只保留「停止 / 复制日志 / 关闭」——写入动作留在常规页，避免运行中还能重复点开始。
- **格式按内容嗅探**，不看扩展名：首个非空白字符 `[` → JSON 数组、`{` → JSON Lines（每行一篇）、其余按 CSV。因此 `.txt` 里放 JSON 数组也能正确导入。
- **CSV 字段类型**：扫描整份文件逐列统计出现过的类型；整列只有一种类型才用它，出现多种类型则判 `mixed`，写入时逐单元格重新嗅探。用户可在左侧逐字段改选（`objectId` / `string` / `int32` / `int64` / `double` / `boolean` / `date` / `null` / `mixed`）。
	- **不取多数类型**：真实导出里 `NULL` 字面量与数值混排、bigint 列里 int32 占多数都很常见，按多数定类型会让少数派的行整条失败（5 行里 2 行 bigint 被当成 int32 丢掉）。口径与 Compass 的 `pickFieldType` 一致。
	- 必须扫全文件而不是只看前若干行：类型只在末尾几行才暴露的列（典型是导出文件末尾追加的 `NULL` 行）用样本判断会得出错误的整列类型。内存只随列数与预览行数增长，不随文件行数增长。
	- `_id` 的 24 位十六进制（兼容 `ObjectId("…")` 写法）判为 `objectId`；不认这一条，导入后主键会变成字符串，和集合里既有数据查不到一起。
	- `null`/`NULL`/`Null` → null；`t`/`true`/`TRUE`/`f`/`false`/`FALSE` 等 → boolean；整数按范围分 int32/int64，超出 i64 保持字符串；带小数点或指数 double；`YYYY-MM-DD` 与 RFC3339 判 date。
	- 日期嗅探按**字节**比较日期前缀，非 ASCII 值（中文、emoji）直接判 string；不能按字符边界切片，否则中文首个字符是 3 字节，切在第 10 字节会落在字符中间而 panic。
	- 写库时按最终类型**直接构造 `Bson`**，不走「拼 Extended JSON 文本再反序列化」——后者会把 `_id` 退化成字符串。
- **JSON / JSONL** 的字段类型由文档自身携带，左侧不显示类型面板；`{"$oid": …}`、`{"$date": …}` 等包装原样还原。
- **选项**：分隔符（逗号 / 分号 / 制表符 / 竖线，仅 CSV 生效）、空值按 `null`（关掉则写空字符串）。改分隔符或空值策略会重新解析预览。
	- 底部选项行按**底部对齐**：分隔符是「标签 + 下拉框」两行，空值开关只有一行，居中会让开关浮在标签与控件之间；E2E 用两者的 `bottom()` 差值守住这条。
	- 空格子不参与类型解析：无论该列推断成什么类型，空单元格都按上面的选项写成 `null` 或空字符串，不会因「不是整数/日期」把整条文档判坏。
- **坏文档跳过并继续**：解析失败的文档不发到服务端，直接计入失败；写库用 `insert_many(..., ordered: false)`，单条 `_id` 冲突不影响同批其余文档。
	- 只有服务端逐条写错误才算「坏文档」；网络/认证等无法判断落库范围的错误直接中止并报错，不猜。
- **进度与中止**：按 1000 条一批写入，底部实时显示「第 n/m 批，已写入 k 条」；运行中可点「停止」，已写入的批次保留，当前批之后不再写入。
- **结束反馈**：提示「成功 N 条，失败 M 条」（有失败时为 warning 色），弹窗内同时列前 20 条失败原因；随后自动重查本页，新写入的文档立刻可见。

### 3.6 集合右键菜单

侧边栏集合与视图行支持右键（表行菜单不适用：集合没有设计/复制/备份等 SQL 语义）。菜单项固定为：置顶、复制名称、刷新、导出、重命名、导入、删除；视图（只读）不渲染重命名 / 导入 / 删除。

- **置顶**复用表的 `pinned_tables`（键为 `table_tree_key`），不另存一份集合置顶状态。
- **复制名称**写系统剪贴板并提示，与表一致。
- **刷新**重跑该标签页当前查询（标签未打开则只刷新侧边栏），同时重取该库子节点——集合信息/索引随子节点一起失效。
- **重命名**：走 `AppCommand::RenameMongoCollection` → 连接器 `renameCollection`（在 `admin` 库上执行，`from`/`to` 均为 `库.集合` 全名，`dropTarget: false`）。成功后控制器重取对象树并就地改写已打开标签页的标题与对象路径（`merge_renamed_mongo_collection_from`），界面侧再补一次该库子节点刷新——控制器只替换第一层（库列表），该库的集合仍是旧快照。
  - 校验：空名、同名、含 `$`/空字符、系统库（`admin`/`local`/`config`）一律在连接器侧拒绝，界面只做空名与同名的即时提示。
  - 弹框是单输入框，回车即提交；失败保留弹框与错误行。
- **删除**：复用 `AppCommand::DropMongoCollection`，弹框固定展示风险说明（不可恢复）与已知文档数（集合信息未加载时不显示数量，不猜）。成功后 `merge_dropped_mongo_collection_from` 关掉对应标签页并重取该库子节点。
- **导入**：先打开（或激活）该集合标签页，再复用结果条上的导入弹窗（§3.5），因此导入逻辑只有一份。

### 3.7 导出文档

右键「导出」打开与表数据导出同一套外壳（780 宽，页签：常规 / 消息日志）。布局对齐 Compass：**条件不单独占页签**，选「当前筛选条件」后直接在常规页展示对应的 shell 查询。高度随内容收紧：全量导出的常规页只有格式与范围两行，用 320，不留大块空白；条件导出与消息日志页仍为 560。

- **常规**：格式 JSON / CSV / JSONL、范围「全量 / 当前筛选条件」。
  - 格式与范围各占一行，左侧 64px 标签列对齐；格式右侧跟一句作用说明（JSON 适合整体备份、CSV 适合 Excel 但会丢失部分类型信息、JSONL 适合流式/大文件），选中态统一为淡蓝底 + 强调色描边。
  - 选「当前筛选条件」时，范围下方把工作台实际生效的 filter / projection / sort 列成小标签，空值与 `{}` 不显示；三者都为空时提示「等同于全量」，避免用户以为条件被忽略。
- **查询预览**：按 Compass 的「Export results from the query below」拼一条只读 shell 语句——`db.getCollection("<集合>").find(<filter>[, <projection>])[.sort(<sort>)];`。与 Compass 一致，只在范围选「当前筛选条件」时展示：全量导出就是 `find({})`，展示它既无信息量，又容易让人以为还要配条件。条件用集合工作台**已生效的** filter / projection / sort，只读展示、不在弹框里编辑（要改条件回集合工作台改），因此不存在「弹框条件与工作台条件不一致」的状态。
  - 预览框标题右侧带复制按钮（写入系统剪贴板并提示），方便贴到 mongosh 核对条数；预览区随剩余高度伸展、超宽横向滚动。
  - 标题旁的目标胶囊显示 `库.集合`，同名集合不会分不清来源；底部左侧常驻一行「将导出为 %{format}，范围：%{scope}」摘要。
- **消息日志**：点「导出」后先选保存路径，再切到日志页；每页进度追加一行，收尾写「完成」或失败行。
- **分页**：`AppController::mongo_find_page` 按 `skip` 每页 500 条翻页（连接器再夹一次上限），直到 `has_more` 为假。
- **CSV 两段式**：对齐 Compass 的 `DOWNLOAD` → `WRITE`。第一段边分页边把每条文档紧凑化成一行 EJSON 写进临时 `.ejsonl`，同时让 `MongoCsvColumns` 记录字段路径（嵌套字段拼 `a.b`、数组元素拼 `a[0]`，`{"$oid":...}` 这类单键 `$` 包装对象按叶子处理）求列并集；第二段按并集写表头和数据行。列并集只能扫完全量才知道，所以混字段集合不会静默丢列，代价是进度会分「下载 / 写入」两段。
  - 单格渲染贴 Compass：ObjectId/UUID 转十六进制、Binary 转 base64、`$numberLong` 等取内层标量、日期转 ISO，其余用紧凑 JSON；以 `= + - @` 开头的值前置单引号，防 Excel 公式注入；文件头写 UTF-8 BOM，Windows Excel 打开中文不乱码。
- **落盘**：先写 `<目标>.partial`，全部成功后才改名到目标路径；取消或失败删除临时文件（CSV 的中间 `.ejsonl` 同样清理），不留半截数据。运行中可「取消导出」，取消标记每页检查一次；运行中不允许关闭弹框（只能取消或等待）。

### 5.2 开发构建的帧率（重要）

**用 `cargo run` / `target/debug` 跑时，渲染慢的根因通常是构建档位，不是页面代码。**

GPUI 每帧都在跑 taffy 布局与字体排版，这些开销落在依赖里。仓库根 `Cargo.toml` 因此显式配置：

```toml
[profile.dev]
opt-level = 1

[profile.dev.package."*"]
opt-level = 3
```

没有这段时，debug 构建下依赖全是 opt-level 0。实测同一台机器、同一个 `fluxdb_demo/orders`（12 篇）页面：

| 场景 | 未配 profile | 配置后 |
| --- | --- | --- |
| 空应用 | 5.2 ms/帧 | 0.50 ms/帧 |
| 卡片全收起 | 20.8 ms/帧 | 1.9 ms/帧 |
| 卡片全展开（12 张） | 401 ms/帧 | 32 ms/帧 |
| 表格视图 | 36 ms/帧 | 3.4 ms/帧 |

`sample` 采样 6204 个样本里 5820 个落在 taffy 布局栈上——这正是依赖未优化的特征。改档位后首轮全量编译约 9 分钟，增量构建不受影响。

上表是**行虚拟化之前**的整页渲染成本（12 篇全量构建）。引入虚拟列表 + 整页解析缓存后，逐帧只构建视口内的卡片，成本随视口高度而不是文档条数增长：100 条一页不再需要靠「不要全展开」规避卡顿。表格同理，只渲染可见行。

判断当前跑的是哪种构建：`ls -la target/debug/fluxdb-desktop` 若体积在几百 MB 且 mtime 是刚构建的，就是 debug。release 构建本来就有优化，不需要这段配置。

### 5.3 栈溢出防护（重要）

`tokio::runtime::Runtime::block_on` 在**调用方线程**上 poll future，只借用 runtime 跑 IO。因此驱动代码（尤其 BSON 序列化/反序列化）吃的是调用方栈。

gpui 的后台任务在 macOS 上跑在 GCD worker 线程里，栈仅约 512 KiB。debug 构建下 `listCollections` 序列化请求时曾直接擦到保护页 → `abort()`，表现为 SIGILL / SIGABRT（**不是**可捕获的 panic）。

因此**所有驱动调用必须经 `mongo_run` / `mongo_block_on`**，它们在 8 MiB 栈的临时线程里 `block_on`。包括容易漏掉的三处：

1. `ClientOptions::parse` + `MongoClient::with_options`（建连）
2. 游标 `try_next` / `try_collect`（结果解码）
3. 每条命令本身

`crates/fluxdb-connectors/tests/mongo_live.rs` 里的 `mongo_live_operations_survive_small_caller_stack` 用 192 KiB 栈的线程复现该环境；漏掉放大栈会直接打挂测试进程。

### 5.4 刷新语义

MongoDB 集合与表同级加载，`replace_loaded_children` 的「库级替换」集合必须包含 `ObjectKind::Collection`，否则每次刷新都会把集合清单再追加一遍，侧边栏出现重复行。

## 6. AI 上下文

Mongo 页面只暴露**授权范围内的定位、查询条件与状态**（当前库/集合、筛选/投影/排序、页码、返回条数）。文档值不进首条消息，AI 需要时经有界只读工具按需读取（`mongo_read_documents`）。凭据、连接串、加密载荷永远不进 AI 上下文。

## 7. 已知限制

- 「查看性能指标」置灰，未实现。
- 复制文档只插单篇；批量导入见 §3.5（支持 JSON / JSONL / CSV）。副本的 `_id` 由服务端生成。新增文档的 `_id` 由界面预填（ObjectId），不支持改成别的类型。
- 导入的 CSV 只支持标量字段类型（嵌套对象/数组请走 JSON 路径），文件必须是 UTF-8。
- 删除只支持单篇，没有批量删除；删除后立即重查本页（没有撤销）。
- 集合导出支持 JSON / JSONL / CSV；导出按 `skip` 翻页，集合在导出期间被并发修改时可能漏读或重复某几篇。
- 不提供数据库级备份恢复（`mongodump` / `mongorestore`），导出只是文档级逻辑导出。
- 不支持 SSH 隧道；TLS 相关参数经连接串导入，TLS 页签对 MongoDB 不提供表单。
- 集合重命名只在同库内，不支持跨库移动；视图不能重命名或删除。
- 创建集合首版只支持普通集合；时间序列与 capped 集合暂无创建入口（读取时时间序列按普通集合处理）。
- 不支持表格行编辑、事务、变更流。
