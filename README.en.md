## Quick Start

> Currently only the macOS target is released; Windows / Linux support is planned.

### Run from Source

Prerequisites: install the [Rust toolchain](https://rustup.rs) (edition 2024; a recent nightly or stable Rust is recommended).

```bash
git clone https://github.com/your-account/fluxDB.git
cd fluxDB

# Run the desktop app
cargo run -p fluxdb-desktop
```

### Package the macOS App

Use the repository's packaging script to generate a self-contained `.app` and DMG:

```bash
./scripts/package-macos.sh
```

The script builds a release binary, embeds Homebrew dynamic libraries, ad-hoc signs it, and produces a `.dmg` (tunable via environment variables such as `PROFILE=debug` and `CREATE_DMG=0`).

> The generated bundle is ad-hoc signed and not notarized; distributing it to others may trigger a Gatekeeper block. Users may need to right-click "Open" or run `xattr -dr com.apple.quarantine`.

## About

FluxDB is an open-source **cross-platform database manager / database GUI**, a native desktop app built on **Rust + GPUI**. It bundles a **SQL editor**, table structure management, data browsing and editing, and more, supporting **MySQL, SQLite, and Redis** through a unified connector layer. Whether you're looking for a database tool, a SQL editor, or a Rust desktop app reference, FluxDB is worth a look.

### Core Capabilities

- **Multi-database connectivity**: Supports **MySQL, SQLite, Redis** through a unified connector layer (`fluxdb-connectors`) — one interaction surface for three backends.
- **SQL editor core** (`fluxdb-editor-core`): A standalone, business-decoupled general-purpose editor with syntax highlighting, code folding, Inlay/Block rendering, and a BlockMap/DisplayMap layered text model.
- **Smart completion**: Keyword/table/column-level SQL completion with a documentation panel and semantic alignment.
- **Table structure management**: Schema browsing, column info panel, DDL editor, table creation (including foreign keys), and table hover preview cards.
- **Data editing**: Editable result write-back, mock data generation, SQL formatting, query history, workbench history, user management, and an embedded Redis terminal.

### Architecture Layers

```
apps/fluxdb-desktop          Desktop entry point (GPUI app, content views, editor components)
├─ crates/fluxdb-app         App layer: query, completion, table info, data editing, Redis commands, etc.
├─ crates/fluxdb-core        Core layer: connections, connectors, data pagination, terminal, users/workbench
├─ crates/fluxdb-connectors  Connector layer: common / mock / mysql / sqlite / redis
├─ crates/fluxdb-editor-core Generic editor core (syntax, folding, Inlay/Block, text model)
├─ crates/fluxdb-editor-language  Editor language adapter protocol
└─ crates/fluxdb-storage     Storage layer
```

Design highlights:

- Pure Rust, frontend and backend in one process (no WebView rendering dependency).
- Editor core strictly decoupled from business logic; independently testable.
- Unified connector abstraction — adding a new data source only requires implementing a set of traits.

## Current Status

### Completed

- **MySQL**: Connection management, SQL editor with completion, table structure browsing/management (create/alter table, DDL), data browsing with editable write-back, SQL file execution, data export, backup list.
- **SQLite**: Base capabilities with the same interaction as MySQL.
- **Redis**: Connection overview, key/value browsing and editing, workbench, embedded terminal commands.

### Commitment

- Will **actively fix reported bugs**.
- Will **gradually expand database support**; the connector layer is designed as a pluggable abstraction, so adding a data source only requires implementing a set of traits.

## Roadmap

## Acknowledgments

This project stands on the shoulders of the following open-source work, to which we are **deeply grateful**:

- **[zed](https://github.com/zed-industries/zed)** — The origin of the GPUI ecosystem. Its component tree, editor, and performance tuning practices are our living textbook; our editor core and UI layering draw directly on its engineering approach.
- **[gpui-kit](https://github.com/longbridge/gpui-kit)** — Supplies base components GPUI lacks (inputs, dialogs, widget library), significantly accelerating UI development and interaction completeness.
- **[dbx](https://github.com/t8y2/dbx)** — Provides an important reference model for multi-database abstraction and connection management.
- **[RedisInsight](https://github.com/RedisInsight/RedisInsight)** — The de facto standard Redis visual client; our Redis details, key/value browsing, and ioredis reuse are architecture-influenced by it.

Without these projects, FluxDB would not have started from such a high bar.
